# 업무 관리 도구 — 6단계 실행 프롬프트

PRD.md §8 마일스톤과 1:1. 새 세션에서 그대로 붙여 넣으면 이어서 할 수 있게 썼다.
각 단계 끝에 「완료 조건」이 전부 맞아야 다음 단계로 간다.

## 1단계 — M1 판 (localStorage)
```
task_management/PRD.md를 읽고 M1을 만들어라.
- task_management/web/index.html: 단일 파일, 외부 의존 0. 저장은 localStorage(키 tm), 데이터 모양은 PRD §3 그대로(tm/meta·tasks·log). 스토어를 load/update(path,value)/subscribe 3함수로 감싸 M2에서 Firebase로 갈아 끼울 수 있게.
- 파서 parse(line, defaultArea, today, tasks)는 순수 함수, /*PARSE-START*/…/*PARSE-END*/ 마커 사이. 문법은 §4.2 표 전부. 토큰은 앞에 공백이 있을 때만. 실패 없음.
- 화면: 오늘(§4.1 묶음 순서, 빈 묶음 안 그림) · 전체(§4.4) · 검토(M1은 빈 상태 + 검토 요청 단추) · 상세 시트(§4.3) · 설정(§4.6 중 JSON/MD 복사·빌드 스탬프·시험 기간). 폰 하단 탭 3 + 하단 고정 입력창, PC는 상단 입력창. 행 48px·글자 16px+·단추 44px+. 안내문·범례 없음.
- 입력창 동작 §4.2 전부(포커스 유지·낙관적 렌더·5초 되돌리기·타이핑 중 필터·칩 미리보기·칩 탭).
- task_management/_test_taskboard.js: node로 index.html을 읽어 vm으로 parse·묶음 함수를 뽑아 검사. §4.2 예시 4줄 + 날짜 토큰 전부 + >id 수정 + 공백 규칙 + 실패 없음. 변이 4종 이상이 FAIL하는지 확인.
- 브라우저 실측: 390px 폭에서 25개 입력·상태 순환·상세 시트·새로고침 후 유지.
완료 조건: 검사 전부 통과 · PC 브라우저에서 25개 입력·상태 변경이 된다.
```

## 2단계 — M2 동기화·이사
```
task_management/PRD.md §6·§7·§8 M2. 순서를 지켜라.
1. .gitignore에 task_management/_backup/·_import/가 있는지 git check-ignore로 확인(2026-09-03 추가됨).
2. Firebase 프로젝트 신설(id는 PRD §9-6 교사 답. 실패 시 my-tasks-e28cb 재사용). firebase projects:create → RTDB 생성 → Auth 이메일/비번 켜기·사용자 T 생성·가입 끔·이메일 열거 보호(콘솔은 교사가).
3. task_management/database.rules.json(§6 규칙 중 T 절만) · firebase.json(public: web, index.html no-cache) · .firebaserc. 규칙·호스팅 배포는 교사 터미널에서.
4. index.html: /*CONFIG-START*/ firebaseConfig /*CONFIG-END*/ + T_UID. compat SDK CDN 판 고정. 스토어를 RTDB 필드 경로 update()로. 스냅샷 캐시(memo 제외·24h 만료). 로그인 화면. 「읽기 전용 · 마지막 동기화」 표시. 빌드 스탬프.
5. _cli.js import <csv> [--write] · backup — CLI 소유자 경로. database:set/update는 -f --project 필수. 쓰기 전 backup.
6. 노션: Last edited time 추가 → 필터 해제 → CSV 내보내기 → _import/notion.csv → dry-run → CSV 수정 → --write → 폰에서 건수 대조 → 노션 잠금.
7. iOS/Android 홈 화면 추가 확인.
완료 조건: 폰 로그인 후 재실행에도 유지 · 폰과 PC가 같은 목록 · 건수 대조 일치 · 노션 잠금 · git check-ignore 확인.
```

## 3단계 — M3 Claude 읽기·쓰기 ★계속 만들지의 관문
```
task_management/PRD.md §5.1·§6 B 절·§8 M3.
1. Auth 사용자 B 생성(콘솔, 교사). 규칙에 B 절 추가(§6 전체) → 배포(교사 터미널).
2. _cli.js setup/pull/add/note/check — B는 REST + idToken(signInWithPassword, apiKey·databaseURL은 index.html 마커에서). 비밀은 %USERPROFILE%\.config\taskboard\bot.json. CLI는 비밀·URL을 출력하지 않는다(오류에도).
3. .claude/settings.json permissions.deny에 Bash(firebase database:*)·Bash(firebase deploy*).
4. 규칙 검증: 봇으로 title 쓰기·교사 체크 text 덮어쓰기·reviewReq 켜기·status:done 생성이 PERMISSION_DENIED인지 REST로 실제 확인.
5. _재개지점.md 머리에 「행정·행사 할 일은 도구에 → node task_management/_cli.js pull」 한 줄. 작업노트/업무관리도구.md 신설(세션 시작 3줄 규칙·명령표) + README 등록.
완료 조건: 새 세션이 pull을 돌리고 지남이 있을 때만 말한다 · 4번 전부 거부 · USB에 비밀 0건(git grep + 파일 검색).
```
