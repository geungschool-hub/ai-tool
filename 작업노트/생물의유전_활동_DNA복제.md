## 2026-08-31 ⑤ — 「답했는데 안 열려」 — 죽은 단추 2개 + **오답 영구 잠금**을 고쳤다

> 교사 신고: 「**카드 2 문항 답했는데 복제 무대 섹션이 안 풀려**」

파고 보니 **둘이 겹쳐** 있었다.

### (가) 단추 2개가 죽은 채로 남았다 — `applyLocks` 는 한 방향으로만 끈다
```js
['btnUnwind', … ,'pick_top','pick_bot'].forEach(function(id){
  if (!c3) setDisabled(id, true);        // ★끄기만 하고 켜 주지 않는다
});
```
켜는 일은 `updateStage()` 가 맡는데(1884~1893행), 거기에 **`pick_top`·`pick_bot` 만 빠져 있었다.**
→ 카드는 열리는데 「위/아래 주형에 붙이기」 두 단추가 **영영 눌리지 않았다.**
고침: `updateStage()` 에 `setDisabled('pick_top', strandComplete(state.newTop))` 두 줄 추가.

★**헤드리스 검사가 이걸 못 잡은 까닭** — 검사는 단추를 누르지 않고 `M.unwind()` 처럼 **함수를 직접 부른다.**
그래서 `disabled` 가 걸려 있어도 다 통과한다. 이제 [6]에
**「열린 직후 꺼져 있어도 되는 단추는 `btnPrimer`·`btnAuto`·`btnLigate` 셋뿐」**을 이름으로 못박았다 —
여기 없는 단추가 꺼져 있으면 되살리는 곳을 빠뜨린 것이다.

### (나) 오답이면 ③ 이 영영 안 열렸다 → **「답하면 열림」으로 바꿨다**
`pickQ` 가 두 번째 호출을 무시(`if (typeof state.qa[id] === 'number') return;`)하고
잠금은 `qCorrect` 를 봤다. 즉 **d1 을 한 번 틀리면 「🔄 처음부터 다시 하기」 말고는 길이 없었다.**
검사에도 `'★한 번 고르면 바뀌지 않는다'` 로 **의도한 동작처럼 박혀** 있었다.

**교사 결정(2026-08-31): 메셀슨·스탈과 같은 규약으로 맞춘다.**

| | 전 | 후 |
|---|---|---|
| 잠금 조건 | `qCorrect('d1', …)` **정답** | **`qAnswered('d1')` 답했는가** |
| 답 고치기 | 못 함(두 번째 호출 무시) | **몇 번이든 고칠 수 있다** |
| 선택지 | 답하면 `disabled` | 계속 누를 수 있다 |
| 진행 5단계 | 정답 기준 | 답함 기준 |

정답·해설은 답한 즉시 그대로 보여 준다 — **막아 두어야 배우는 것이 아니다.**
한 번 연 문은 다시 오답으로 고쳐도 닫지 않는다(검사가 문다).

**검사**: 1187 → **1192단언 · 실패 0**. **변이 6종 전부 FAIL 확인** —
되살리는 줄 지우기(1) · 잠금을 「정답이어야」로(2) · 답 고치기 막기(2) · 선택지 다시 잠그기(1)
… 그리고 앞 절의 색·차례 변이 4종.

⚠ **다른 활동도 훑어볼 것** — `qCorrect` 를 잠금에 쓰는 활동이 또 있는지.

## 2026-08-31 ④ — 격자의 **염기 색을 되살리고**, 무대를 **염기 단추 바로 위**로 옮겼다 (교사 지시)

> 교사: 「복제 무대 섹션에 **주형 가닥이 너무 연해서 안 보여**. 그리고 버튼을 클릭해서 새로운 염기를 놓을 거면
> **염기가 그림 옆에 있어야** 보기 편하지 않겠어? 아니면 **바로 아래에** 있던가」

### ★연했던 진짜 까닭 — CSS 차례 문제였다 (색을 옅게 준 적이 없다)
`.b-A ~ .b-C`(114행)가 염기 색을 주는데, **`.cell`(148행)이 그보다 뒤에 있으면서**
`color:#BBB` 와 `border:1.6px solid #D5DAE0` 를 **단축 속성으로 덮고 있었다.**
둘 다 **1-클래스 특이도**라 **나중에 선언된 `.cell` 이 이긴다.**
→ 격자의 모든 염기 타일이 **회색 글자 + 회색 테두리**로 나오고 있었다. 주형 가닥만의 문제가 아니었다.

고침: **2-클래스 규칙**으로 되살렸다. `.cell.b-A { color:var(--red); border-color:var(--red); }` … 4개.
`.cell.nt.locked / .openslot / .target`(3-클래스)은 그대로 이기므로 **빈 칸의 회색·점선은 안 건드린다.**
덤으로 아직 안 풀린 칸의 흐림을 **`.72 → .82`** 로 올렸다(색이 살아났으므로 더 내릴 까닭이 없다).

★**이 함정은 이 파일 어디서든 되풀이될 수 있다** — 색 클래스(`b-*`)보다 뒤에 오는 단축 속성(`border:` `color:`)은
같은 특이도면 무조건 이긴다. 새 타일류를 만들 때 **선언 차례를 확인할 것.**

### 무대를 카드 가운데로 내렸다
카드 ③ 안 차례를 **격자 → 1·2·3·4단계 패널** 에서 **1·2단계 → 격자 → 3·4단계** 로 바꿨다.
이제 격자 **바로 밑**이 3단계의 **A·T·G·C 단추**다(교사가 준 두 갈래 중 「바로 아래」).
★**1~4단계 패널의 차례는 건드리지 않았다** — 그 차례가 교과서 49쪽 문항 2의 정답
「프라이머 합성효소 → DNA 중합효소 → DNA 연결효소」이기 때문이다.
「옆에」는 버렸다 — 격자가 1002px라 옆에 두면 태블릿(820px)에서 무너진다.

**검사**: 1168 → **1187단언 · 실패 0**. [16]에 ①`.cell.b-*` 네 규칙과 색 짝 ②안 풀린 칸 opacity ≥ .8
③무대·1~4단계의 앞뒤 차례와 「무대~염기 단추 사이 600자 미만」을 넣었다.
**변이 4종 전부 FAIL 확인** — 규칙 지우기(3) · 흐림 되돌리기(1) · A에 T색 짝짓기(2) · 무대를 맨 위로(2).

## 2026-08-31 ② — 중합효소가 **붙고 → 이동하며 → 뒤로 깔린다** (교사 지시)

> 교사: 「프라이머 붙는 위치는 알겠어. 그런데 **중합효소가 등장하는 방향이 정작 중합하는 방향의 반대**라서 이상해」
> → 「**중합효소가 붙고 이동하면서 중합되는 식으로 애니메이션을 짜야될 것 같은데?**」

**무엇이 문제였나.** 「붙는다 · 이동한다 · 새 가닥이 생긴다」 셋이 **한 국면에 뭉쳐 있었다.**
④를 누르면 프라이머는 오른쪽 끝(29~31)에 있는데 중합효소가 **왼쪽 끝 24번에 불쑥 나타나고**
새 가닥 24~28이 동시에 깔렸다. 학생 눈에는 중합효소가 **도착지에서 거꾸로 등장**한 셈이라,
「프라이머의 3′ 말단에서 시작해 그쪽으로 나아간다」는 인과가 통째로 사라졌다.

**고친 방식 — 국면을 11 → 13개로 늘려 사건을 쪼갰다.**

| | 전 | 후 |
|---|---|---|
| ④ | (없음) | **중합효소가 프라이머의 3′ 말단에 붙는다 — 새 가닥 0칸** |
| ⑤⑥ | 새 가닥+중합효소가 한꺼번에 등장 | 중합효소가 **이동**하고 지나간 자리에 새 가닥이 **뒤따라** 깔린다 |
| ⑧ | 되돌아오며 조각까지 한꺼번에 | **되돌아와 새 프라이머에 붙기만** 한다 |
| ⑨ | (없음) | 되돌아온 중합효소가 **이동하며** 또 하나의 조각을 만든다 |

**불변식 하나로 정리된다 — 「중합효소는 늘 자기 가닥의 3′ 말단에 있다」.**
아직 아무것도 안 만들었으면 프라이머의 3′ 말단(위 29 · 아래 26·18), 만들고 있으면 그 조각의 3′ 말단.
검사가 **전 국면 전수로** 이것을 문다. 예외가 없다.

**곁딸린 것**: `fkSpread` 가 `fork <= 0` 이면 1을 돌려주게 했다 — 전에는 다 풀린 뒤에도
**왼쪽 끝 3칸이 덜 벌어진 채**로 남아(간격 37px / 84px) ⑫ 「딸 DNA 2개」가 왼쪽에서 붙어 보였다.

**검사**: 1052 → **1166단언 · 실패 0**. 국면 번호를 박지 않고 `FK_ATTACH_PH` 따위 이름 상수를 쓰게 고쳤다.
**변이 7종 전부 FAIL 확인** — 도착지 등장(2건) · 붙는 국면에 새 가닥(3) · 안 지나간 자리에 새 가닥(3) ·
중합효소를 5′ 끝에 두기(3) · 지연 없애기(2) · `FK_MOVE` 어긋내기(1) · 프라이머 선행 틈 없애기(1).

🟡 **실측 필요**: ④에서 중합효소 배지(r=12)가 프라이머 캡슐 위에 얹힌다 — 빗금이 가려 안 읽히지는 않는지.

## 2026-08-31 ① — 무대를 **사다리 모양**으로 폈다 (교사 지시)

> 교사: 「애니메이션에서 굳이 **이중 나선의 형태에서 갈라지게 하지 말고 그냥 사다리 형태에서 갈라지게** 해야
> 그 이후의 **방향성 부분에서 헷갈리지 않을** 것 같아.」

**무엇이 문제였나.** 8/28 판은 아직 안 풀린 구간을 `sin` 파로 꼬아 그렸다.
꼬면 두 가닥이 주기마다 **교차하며 위아래 자리를 바꾼다.** 그런데 이 무대가 곧바로 가르치려는 것이
**5′·3′ 방향과 「위 주형 / 아래 주형」**이다. 「지금 위에 있는 저것이 아까 그 가닥인가」가 흐려지면
④⑤의 두 화살표 방향 비교가 통째로 무너진다. **표현의 멋보다 방향 감각이 먼저다.**

| 무엇 | 전(8/28) | 후(8/31) |
|---|---|---|
| 붙어 있는 구간 | `150 ± FK_AMP·sin(2π i/FK_PER)` (`AMP=13` `PER=6`) — 교차함 | `150 ∓ FK_LAD` (`FK_LAD=11`) — **교차 없음** |
| 가로대 | `scale(1, |wave|/AMP)` 로 길이가 변하고 교차점에서 0 | 길이 `±FK_LAD` **일정**, 벌어지면 사라짐 |
| 옮기는 함수 | `fkSet` + `fkSetS`(scale 전용) | **`fkSet` 하나** — `fkSetS` 삭제 |
| 국면 0 이름 | `감긴 이중나선` | `두 가닥이 붙어 있다` (설명체 `~다` 로 통일) |
| 국면 0 자막 | 「두 가닥이 서로 꼬여 붙어 있다」 | 「…실제 DNA는 꼬여 있으나, 두 가닥의 **방향**을 보기 쉽도록 사다리 모양으로 폈다」 |
| d1 문항 | 「아직 **감긴** 구간과…」 | 「아직 **붙어 있는** 구간과…」 (그림과 말이 어긋나지 않게) |

★**꼬임을 없앤 대신 「실제 DNA는 꼬여 있다」를 자막에 명시**했다 — 사다리가 실물이라고 오해하게 두지 않는다.

**검사**: 1006 → **1052단언 · 실패 0**. [11]의 `/선$/` 특례([감긴 이중나]`선`)도 함께 걷어내
국면 이름은 **예외 없이 `~다`** 로 끝나게 죄었다.
**변이 4종 전부 FAIL 확인** — 사인파 되살리기(10건) · 간격 흔들기(9건) · 가로대를 벌어진 칸에 남기기(11건) · 국면 이름을 명사로(1건).

🟡 **브라우저 실측은 아직 못 했다** — 확장이 연결돼 있지 않다. 사다리 폭 22px(칸 높이 9px → 빈틈 13px)이
태블릿에서 사다리로 읽히는지, 가로대가 칸에 가려 안 보이지는 않는지는 **눈으로 확인이 필요하다.**

## 2026-08-28 개편 — 「너무 정적이다」를 고쳤다

> 교사 발주: 「지금은 일단 너무 정적인데다가 **기존의 이중 가닥이었던 DNA가 단일가닥으로 나뉘어서
> 양쪽의 가닥에서 다른 복제 과정이 벌어지는 걸 전혀 보여주지 못하는 것** 같거든.
> 좀더 아이들이 흥미를 느낄 수 있도록 **복제 과정을 단계별로 나누어서** 보여주고
> **각 과정에 작용하는 요소들, 예를 들어 프라이머라든가 복제 효소 같은 것들**을 아이들이 파악할 수 있게 하고 싶어.

검사가 이것을 문다 — `L(7).polT.col ≠ L(6).polT.col` **AND** `L(7).polB.col === L(6).polB.col`.

이름을 달아 두었다 — **검사는 숫자를 박지 않고 이 상수를 쓴다**(대본이 또 늘어도 안 깨진다).

### 발견 구조를 지킨 장치 3가지
1. **국면 0~2 에는 새 가닥·프라이머·효소를 하나도 그리지 않는다** (표준 §4 분리 국면 규칙).
2. **무대에 염기 글자(A/T/G/C)를 한 자도 쓰지 않는다** — 카드 ③의 답을 미리 알려 주지 않는다.
3. **마지막 국면(⑩)만 잠근다** — `fkCap() = ligated ? 10 : 9`.
   ③에서 조각을 이어야 열리며, 그 시점은 격자에 「(지연 가닥)」 이름표가 뜨는 때와 **정확히 같다**(검사가 이 짝을 문다).

### 그리는 법
- 칸마다 `<g>` 를 **한 번만 짓고** transform·opacity 만 바꾼다(chromolab 방식). 물체 193개.
- 감김 ↔ 벌어짐은 `fkSpread(i,fork) = clamp((i−fork+1)/FK_RAMP, 0, 1)` 하나로 낸다. `FK_RAMP=4` 칸이 Y자의 목이다.
- **아직 붙어 있는 구간은 사다리다** — 위 주형 `150 − FK_LAD`, 아래 주형 `150 + FK_LAD` (`FK_LAD=11`), 벌어지면 108 / 192.
  **꼬아 그리지 않는다**(2026-08-31 교사 지시, 아래 절 참조).
- **염기쌍 가로대는 두 가닥 사이를 실제로 잇는다** — 길이 `±FK_LAD` 로 일정하고, 벌어진 칸에서는 사라진다(`op:0`).
- ★**이동하며 중합되는 연출**은 타이머 없이 **칸마다 `transition-delay`** 로 낸다.
  `fkStagger(ph, prev)` → `fkSweep()` 가 「이번 국면에 새로 켜지는 칸」에만
  `FK_MOVE × |i − 출발칸| / |도착칸 − 출발칸|` 초의 지연을 준다. 중합효소가 지나가는 뒤로 칸이 깔린다.
  **한 걸음 앞으로 갈 때만** 준다 — 되감기(◀ ⏮)·건너뛰기에서는 지연 0.
  프라이머가 새로 놓인 국면에서는 중합효소가 `FK_PMR_LEAD` 만큼 늦게 움직인다(놓인 뒤에 붙는 차례가 보이게).
- 물체를 옮기는 함수는 `fkSet(id,x,y,op)` **하나뿐**이다 — 길이를 늘이던 `fkSetS` 는 사다리로 바꾸며 없앴다.
- 순수 함수 `fkFrame(ph) → fkLayout(ph) → fkApplyPhase(ph)`. **검사는 `fkLayout` 을 직접 문다**(문자열 grep 금지).

## ★프라이머를 물체로 만들었다 — 이번 개편의 핵심

개편 전에는 「각 조각의 **첫 칸이 프라이머 역할**을 한다고 보자」고 **글로만** 얼버무렸다.
이제 학생이 **[🧬 프라이머 놓기]** 로 직접 놓는다. 셋이 한꺼번에 풀린다.

1. **교과서 49쪽 1-(3)** 「선도와 지연에 필요한 프라이머 수는 같다 → ×」가
   학생이 놓은 개수 **위 1개 · 아래 4개**로 **세어진다**. 그림 Ⅰ-32 도식에도 선도 1개·지연 2개가 그려져 있다.
2. **교과서 49쪽 문항 2** 의 정답 「**프라이머 합성효소 → DNA 중합효소 → DNA 연결효소**」가
   **단추 차례 그대로**가 된다(③ 카드의 1~4단계 패널).
3. **막혀서 발견하는 자리가 하나 늘었다.** 프라이머 없는 조각을 누르면
   「⛔ 이 자리에는 아직 3′ 말단이 없다」로 막힌다.

### 구현 — `placementCheck` 를 건드리지 않았다
3′ 말단 규칙은 이 활동의 심장이고 기존 단언이 물고 있다. 그래서 **별도 함수 `primerCheck(strand, idx, prim)`** 를 두고
`tapCell`·`placeBase`·`selectStrand` 가 **먼저** 묻게 했다. 기존 5개 사유(ok/notopen/filled/wrongend/blocked/range)는 그대로다.
- 캡슐은 **칸을 먹지 않는다** — `.primerrow` 라는 별도 행에 `left:(slot×26)px; width:78px`(3칸)로 얹는다.
  위는 29번 칸, 아래는 조각의 왼쪽 끝(0·8·16·24번).
- `mergeState` 가 앞뒤를 맞춘다 — 붙인 칸이 있는 조각은 프라이머가 놓였던 것으로 되돌린다.
- ⚡자동 합성도 **프라이머를 먼저 놓는다**(규칙을 건너뛰지 않는다).

## 격자(카드 ③)에 넣은 것

- **염기 타일의 색은 `.cell.b-A~C`(2-클래스)가 준다** — `.b-A`(1-클래스)만 두면 `.cell` 이 덮는다(위 ④ 절).
- **열린 칸이 위아래로 벌어진다** — `splayOf(idx, unwound) = min(10, 2 + 1.2·d)` px.
  위 주형·새 가닥①은 `top:-dy`, 아래 주형·새 가닥②는 `top:+dy`. **`transform` 이 아니라 `top` 을 쓴다** — 오답 흔들림(`shake`)과 부딪히지 않기 위해서다.
- 결합 행 `‖` 는 **지우지 않고** `.bondc.cut` 으로 흐리게 한다(칸 높이를 지켜 행이 튀지 않게).
- **중합효소 배지**가 지금 붙일 수 있는 3′ 말단을 따라다닌다(위·아래 각 1개, 프라이머가 있을 때만).
- **연결효소 마름모** 3개가 이은 뒤 이음매(8·16·24번)에 나타난다.
- 프라이머 캡슐의 방향은 **글자가 아니라 촉**으로 준다(`.pmr-cap::after`) — 빗금 위의 작은 글자는 읽히지 않았다(실측).

## 함정 (다음에 손댈 사람이 볼 것)

- ★★**헤드리스 검사는 단추를 누르지 않는다 — 함수를 직접 부른다.** 그래서 `disabled` 가 잘못 걸려 있어도

- ★**헤드리스 검사에 `Date` 가 없다** — `badgeTap` 은 `typeof Date !== 'undefined'` 로 감쌌다.
- ★**`_missing` 은 「HTML 에 없는 id」가 아니라 「이어 붙여 만든 id」만 잡는다** —

- ★**`shake` 애니메이션이 `transform` 을 쓰므로 벌어짐에 `transform` 을 쓰면 서로 지운다** → 벌어짐은 `top`.
