## 다른 앱들과 다른 점 — 백엔드가 Firebase가 아니라 **Supabase**
영상 업로드 때문에 Storage가 필요해서 Supabase를 씀. 이 저장소에서 유일.
- 프로젝트: `svqaelxrdzavqbydptnt` (Region: Northeast Asia / Seoul)
- 스키마 정본 `supabase/schema.sql` 한 파일 → SQL Editor에 통째로 붙여넣고 Run.
  `create table if not exists` / `create or replace function` / `on conflict do nothing` 구조라
  **몇 번을 다시 실행해도 안전**하고 기존 데이터도 안 지워짐. 스키마를 고치면 재실행이 정식 배포 절차.
- 인증은 Supabase Auth가 아니라 **자체 구현**: 학번+PIN → `login` RPC → `session_token`(uuid) 반환.
  테이블 직접 접근이 아니라 전부 `security definer` 함수(RPC)를 거친다.
- 저장 용량: 무료 요금제 파일 1GB / 월 전송 5GB. 10초 영상 2~4MB라 용량은 여유,
  **학생들이 많이 돌려보면 전송량이 먼저 소진**될 수 있음 (Settings → Usage).

## ★함정 — Supabase의 pgcrypto는 `public`에 없다 (2026-07-21 실제로 터짐)
`create extension if not exists pgcrypto;` 를 써도 Supabase는 이미 **`extensions` 스키마**에
깔아 둔 상태라 no-op이 된다. 그래서 함수에 `set search_path = public` 만 걸어 두면:

```
function crypt(text, text) does not exist   (42883)
```

→ 가입·로그인·PIN초기화가 **전부** 죽는다. 겉으로는 앱이 멀쩡해 보이고 눌러야 알 수 있음.

**해법 (schema.sql에 반영됨)**
- `create extension if not exists pgcrypto with schema extensions;`
- `security definer` 함수 전부 `set search_path = public, extensions`

**교훈**: Supabase에서 `security definer set search_path` 를 쓸 때 확장 함수(crypt·gen_salt 등)를
호출한다면 `extensions` 를 반드시 함께 넣을 것. `gen_random_uuid()` 는 pg_catalog라 안 걸려서
"일부만 되는" 착시가 생긴다.

## 진단 요령 — 브라우저 없이 원격 점검
학교망/브라우저 없이도 anon key로 상태 확인이 가능하다 (`web/config.js`에 URL·키 있음).

```bash
KEY=$(grep -o 'eyJ[A-Za-z0-9._-]*' web/config.js | head -1)
URL="https://svqaelxrdzavqbydptnt.supabase.co"
# 스키마 적용됐나 (200이면 있음)
curl -s --ssl-no-revoke -o /dev/null -w "%{http_code}\n" "$URL/rest/v1/students?select=*&limit=1" \
  -H "apikey: $KEY" -H "Authorization: Bearer $KEY"
# 가입/로그인이 실제로 되나 (없는 계정으로 호출해 에러 메시지를 본다)
curl -s --ssl-no-revoke -X POST "$URL/rest/v1/rpc/login" -H "apikey: $KEY" \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"p_student_no":"__x__","p_pin":"0000"}'
```
- 테이블명 오타로 404가 나면 스키마 미적용으로 오판하기 쉽다. 정확한 이름은
  students · books · **setlog_days** · **setlog_videos** · reactions (+ `v_` 뷰들).
- `curl` 은 `--ssl-no-revoke` 필요 (schannel 폐기검사 실패 회피).
