## 무엇을 하는가
- 클릭으로 조립 — `＋부부` 로 시작, 사람을 고르면 `＋아들 ＋딸 ＋배우자 ＋형제 ＋부모`
- **형질 최대 3개**. 사람마다 발현을 체크하면 **조합에서 무늬가 정해지고 범례가 자동으로 생긴다**
- **PNG 복사**(한글에 Ctrl+V) · PNG 내려받기 · **복습 퀴즈용 데이터**(`_pedigree_svg.js` 규격) · JSON 저장/불러오기
- **범례만 따로 뽑기** — 그림에서 「범례 자리 = 없음」으로 빼 두고 범례는 따로 붙일 수 있다.
  그림 안 범례와 **같은 함수(`legendBlock`)가 그린다** — 두 벌이 되면 반드시 어긋난다
- **가계도에서 더블클릭 = 그 사람 삭제** (자녀가 딸려 있으면 먼저 물어본다)
- 칸마다 **「⟲ 이 칸 기본값으로」** — 그 칸이 다루는 것만 되돌린다. **가계도 자체는 안 건드린다**
- **판정 도우미** — 네 가정(상우·상열·X우·X열)을 다 대입해 보고, 안 되는 것은 **어느 구성원 때문인지** 말한다.
  가정이 하나만 남으면 유전자형을 계산하고, **부모가 확정될 때만** 다음 자녀 확률을 낸다.

## ★무늬 = 조합 비트마스크 (이 한 줄이 설계의 전부다)
가=1 · 나=2 · 다=4 → **조합 값이 그대로 무늬 번호**가 되도록 팔레트 차례를 짰다.

```
0 흰색 · 1 빗금／ · 2 격자⊞ · 3 회색채움 · 4 점무늬 · 5 역빗금＼ · 6 가로줄 · 7 검정채움
```
→ (가)=빗금 · (나)=격자 · **(가)+(나)=회색** 이 저절로 나온다 = 예시 이미지와 일치.
★**3번 자리에 회색이 와야 한다.** 흔한 차례(회색을 뒤로)로 놓으면 (가)+(나)가 점무늬가 되어 어긋난다.
형질이 1개일 때만 예외로 발현=검정(중간고사 6번 양식). 팔레트에서 바꾼 것은 `fillOverride` 에 남는다.

## ★배치 — 「오른쪽으로만 밀기」
① `walkOrder` 로 세대마다 읽는 차례를 정하고 ② 오른쪽으로만 밀어 맞춘다(부부를 자녀 중심으로 / 세대별 최소 간격).
오른쪽으로만 움직이므로 반드시 멈춘다.

**이 방식이 예시 이미지 2번(집안을 잇는 결혼)을 스스로 재현한다** — 그 그림은 부부 6—7 의 간격을
형제 간격보다 넓혀서(124 대 82) 7이 자기 부모 아래 오게 풀었는데, 밀기가 같은 해법에 도달한다.

### 겪은 것 — 배치가 폭주했다
DFS 방문 차례를 그대로 줄 차례로 쓰면 **아랫세대가 윗세대와 뒤집히는** 가계도가 생긴다
(16의 부모가 17·18의 부모보다 오른쪽인데 16이 왼쪽에 오는 경우). 그러면 밀기가 서로를 영원히 쫓아
**폭이 210 → 5,650 까지 벌어졌다.**
→ **DFS 는 「집안이 늘어서는 차례」만 얻는 데 쓰고, 세대마다 줄은 부모의 차례를 따라 다시 세운다.**
무작위 4,000건에서 불안정 0 · 겹침 0 · 폭주 0 을 확인했다.

★**배우자의 친가를 먼저 데려오는 가지**(`walk(ch.top, s)`)는 없어도 되는 코드처럼 보이지만 아니다 —
빼고 600건을 돌려 보니 62건에서 배치가 달라지고 한 건은 폭이 3,490 이 됐다. 검사가 그 자리를 문다.

## 함정 (전부 실제로 걸렸다)
| 함정 | 왜 |
|---|---|
| **번호를 도형 아래 두면 ROW 42 로는 안 된다** | 번호가 형제 가로선을 밟는다. `ROW ≥ 번호기준선19 + 내림3 + 여유8 + 가로선22 = 52`. 원안 6번이 42인 것은 번호를 **도형 안**에 넣었기 때문이고, 9번은 실제로 52다 |
| **`<pattern>` id 는 렌더마다 달라야 한다** | 한 문서에 SVG 가 여럿이면 같은 id 의 `<defs>` 가 여러 벌 생기고 `url(#x)` 는 **첫 것만** 잡는다(메셀슨 설계재료에 남은 사고) → `renderSeq` 를 접두사로 |
| **PNG 는 외부 참조가 하나만 있어도 안 나온다** | canvas 가 오염돼 `toBlob` 이 막힌다. `data:` URL 로 넘기고 `xmlns`·`width/height` 를 명시해야 `<img>` 가 그린다 |
| 글꼴 이름 하나만 쓰면 래스터화에서 글자가 깨진다 | `font-family="Batang, 바탕, serif"` |
| **새 단추는 `ACT_KEYS` 에 등록해야 한다** | 안 하면 눌러도 아무 일이 안 일어난다. 검사가 화면에 그려진 `<button data-*>` 를 훑어 목록에 다 있는지 본다 |
| ★**무늬 단추가 눌리지 않았다** | 단추 안에 `<svg><rect>` 가 있어 누른 자리가 도형이었다. 위임이 `while (!t.id && !t.dataset) t = t.parentNode` 로 되어 있었는데 **`dataset` 은 모든 원소에 있어서 한 칸도 못 올라간다**. → 「무엇을 하라는 것인지」 붙은 조상을 찾아 올라가는 `actTarget()` 으로 바꾸고 `.pal button svg{pointer-events:none}` 를 함께 걸었다. 교사가 써 보고 알려 줬다(2026-09-10) — 검사가 못 잡던 자리라 `actTarget` 단위 검사를 새로 넣었다 |
| ★**무늬가 도형 한가운데를 안 맞췄다** | `patternUnits="userSpaceOnUse"` 는 **그 도형의 좌표계**로 타일을 깐다. 도형을 절대좌표로 그리면 타일이 **그림 전체 원점**에서 시작해 도형마다 무늬 위상이 제각각이 된다. → 도형을 **원점에 그리고 `<g transform="translate(cx,cy)">` 로 옮긴다**. 타일마다 원점에 무늬가 오게 정의도 고쳤다(점무늬는 네 귀퉁이로, 가로줄은 위·아래 변에, 격자는 마주 보는 변에도 — 안 그으면 타일 경계에서 선이 반만 그려진다). 실측(180° 회전 대조): 격자 46% · 점무늬 81% · 역빗금 94% · 가로줄 84% 어긋나 있던 것이 **전부 0%** 가 됐다. 교사 지적(2026-09-10) |
| **범례 견본이 너무 작았다** | 중간고사 원안 값(견본 10 / 도형 20 = 0.50)을 그대로 썼는데 교사 예시 이미지는 **0.70**(25 px / 36 px)이다. → 범례 크기를 **도형에 견준 비율**로 바꿨다 (견본 0.70 · 글자 0.46 · 줄 간격 견본의 1.32 · 글자 왼쪽 여백 견본의 0.40 — 모두 예시 이미지 실측). 도형을 키우면 범례도 같이 커지고, 「범례 크기」 80~150 % 단추로 따로 조절도 된다. 교사 지적(2026-09-10) |
| ★**무늬 타일이 도형 크기를 안 따라갔다** | 타일이 6units 고정이라 작은 견본에는 굵은 무늬가 들어갔다. → `patternTransform="scale(도형/PAT_BASE)"` 로 **도형 크기에 비례**하게. 본체와 범례가 **다른 id**를 써야 한다(같이 쓰면 한쪽 배율이 다른 쪽까지 바꾼다). 실측: 격자 선 간격 본체 6 · 범례 4.21 = 정확히 0.70배. 교사 지적(2026-09-10) |
| ★**고를 때 무대를 다시 그리면 더블클릭이 죽는다** | `pointerdown` 에서 `render()` 를 부르면 누른 도형이 그 자리에서 사라져 **`dblclick` 이 아예 안 뜬다**(라이브 A/B 로 0건 확인). → `selectPerson()` 은 **표시만 옮기고**(`markSel()`) 오른쪽 칸만 새로 그린다. 고른 표시는 언제나 그려 두고 자리만 바꾼다 |
| **`viewBox` 만 있는 SVG 는 납작해진다** | 범례만 뽑은 SVG 를 크기 없이 넣었더니 높이 0 으로 눌렸다(헤드리스 렌더로 실측). PNG 로 갈 때는 `width/height` 를 명시하고, 미리보기로 쓸 때는 `style="width:100%;max-width:…"` 를 함께 준다 |
| **자식을 더할 때 선택을 자식으로 옮기면 안 된다** | 연달아 누르면 형제가 아니라 자손이 줄줄이 생긴다. 선택은 그 자리에 둔다 |
| 형제 가로선 아래 배우자가 들어오는 것은 **잘못이 아니다** | 결혼해 들어온 사람은 위로 가는 선이 없어 오해가 없다. 부모가 있는 남이 들어올 때만 경고 |
| 퀴즈 데이터는 **행 차례가 곧 그림**이다 | `_pedigree_svg.js` 는 좌표를 안 받고 행 순서로 다시 배치한다 → 행을 **화면 x 순**으로 내보내고, 부부가 떨어지거나 형제가 끊기면 경고한다 |

## 판정 엔진 — 탐색과 규칙을 겹쳐 쓴다
- **판정은 백트래킹 탐색**이 한다(사람마다 유전자형을 대입, 400,000노드 상한).
- **문장은 교과서 국소 규칙 6개**가 만든다. 규칙이 안 걸리는데 탐색이 실패하면 「모순 없이 배정할 수 없습니다」.

| 관찰 | 배제되는 가정 |
|---|---|
| 정상 부 × 정상 모 → **발현** 자녀 | 우성 전부 (상우·X우) |
| 발현 부 × 발현 모 → **정상** 자녀 | 열성 전부 (상열·X열) |
| 정상 아버지 → 발현 딸 | X 열성 |
| 발현 어머니 → 정상 아들 | X 열성 |
| 발현 아버지 → 정상 딸 | X 우성 |
| 정상 어머니 → 발현 아들 | X 우성 |

★아래 두 짝을 뒤집어 쓰기 쉽다 — 「**정상 어머니 → 발현 아들**」이 배제하는 것은 X **우성**이다
(X 열성에서는 어머니가 보인자면 얼마든지 나온다). 「발현 어머니 → 정상 아들」이 배제하는 것이 X 열성이다.
**표현형이 모두 알려진 가계도에서는 이 6개가 완전하다** — 그래서 검사 [9]가
**탐색 판정 = 규칙 판정**을 1,200건 전수 대조한다. 둘이 갈리면 하나가 틀린 것이다.

확률은 **부모 두 사람의 유전자형이 모두 확정될 때만** 낸다. 아니면 「단정할 수 없습니다」라고 말한다
— 모르는 것을 지어내면 시험 문항이 틀린다.
