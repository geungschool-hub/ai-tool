## 과목 분리 구조 (다음 퀴즈 추가 시 이대로)
- 퀴즈 객체에 **`subject:'gen'`** 필드만 붙이면 /gen 화면에 감. **없으면 생명과학.**
- 새 퀴즈 추가 경로 2가지: ① admin.html [＋ 새 퀴즈] + 과목 드롭다운(즉시 반영, 코드 수정 없음) ② index.html SEED에 추가 + 배포(없는 퀴즈만 transaction 시드라 기존 DB 안 건드림).
- `subjectOf()`는 관대 판정('Gen'·'유전'·'genetics'도 gen으로 흡수) — 오타로 유전 문항이 생명과학 화면에 새는 것 방지.
- admin의 저장·백업복원·JSON/엑셀 가져오기 전부 subject 보존 패치됨. 엑셀 18번째 열 '과목(subject)' (빈칸=생명과학, gen=생물의 유전, 미지 값은 기존 유지+경고).

- Node 헤드리스 테스트 50개 단언 전부 통과 — DOM·Firebase 스텁 위에서 실제 스크립트 eval (gene-sim 노트의 패턴 재사용).
- 적대 검증 에이전트 5개(누출·회귀·admin·문항·배포설정): critical 0. 문항 정답 14/14 교과서 일치. major 1건(가져오기 subject 미검증)은 수정 반영.
- **알고 두는 것 (수정 안 한 minor)**:
  - `2단원_복습퀴즈.html`(구형 단독 파일)은 옛 링크 보호용으로 계속 배포 중 — 로그인 없이 접근 가능(1학기부터의 기존 결정).
  - RTDB 규칙상 익명 인증이면 quizzes/ 읽기·쓰기 가능 — 과목 분리는 표시 계층 (기존 보안 posture 그대로).
  - 학생 부팅 시 quizMeta 재작성과 관리자 저장이 겹치면 드롭다운 태그가 잠깐 지워질 수 있음(자가 복구, 학생 화면 무영향).

## 함정 메모
- ★이 학교망은 TLS 검사 프록시 — **curl은 `-k` 없이는 web.app에 exit 35**로 실패한다(github.io는 통과). node는 NODE_TLS_REJECT_UNAUTHORIZED=0이 이미 잡혀 있음.
- 배포는 `quiz activity` 폴더에서 `npx firebase-tools deploy --only hosting --project lifescience-quiz`. **database는 같이 배포하지 말 것**(라이브 규칙 확인 함정 — 1p1t 노트 참조).
- 문항 원본은 DB `quizzes/` 노드. **SEED만 고치고 배포해도 이미 시드된 퀴즈는 안 바뀐다** — 내용 수정은 admin 편집기로.
- 검토 md·문항 출처: `quiz activity/유전1-1_유전의기본원리_복습퀴즈_검토.md` (firebase.json ignore로 비공개).
- quiz activity 자체 git 저장소는 이번 변경 **미커밋 상태**(커밋은 사용자 요청 시에만 — [[commit-only-on-request]]).

## ✅ 심화 10문항 — 기존 퀴즈에 합쳐 반영 완료 (2026-08-12)
- 교사 요청: "10문제 더, 난이도 있게, 가상 대립형질 우열 판정(순종 교배 F₁ 표현형으로 판별) 포함".
- S1~S10 전부 적용·분석형 작성 → 검증 에이전트 3개(교과서 대조·검산·난이도/중복) 통과, 지적 5건(검토표식·S5 조합형 전환·S6 엄밀화·S8 적용형 교체·S10 상향) 반영.
- **반영 방식 = 교사 결정으로 별도 퀴즈 없이 기존 「1-1 유전의 기본 원리」에 합침 → 총 24문항**(심화 = 원본 인덱스 14~23 = 화면 문항 15~24). 기존 진도 보존(첫 14문항 바이트 단위 불변 확인). 완성도 하락 부작용(100%→58%)은 고지 후 수용.
- ★**라이브 반영 방법 기록** — SEED 수정+배포로는 이미 시드된 퀴즈가 안 바뀌므로 **RTDB REST로 직접 병합**했다:
  익명 인증(identitytoolkit signUp, API키는 index.html firebaseConfig) → GET 현재 퀴즈(14문항 확인) → quizBackups/에 자동 백업 POST → 기존 14 + 새 10 합쳐 PUT → quizMeta PUT(totalQuestions 24) → GET 재검증.
  스크립트 패턴은 이 세션 스크래치패드 `merge_advanced_questions.js`(세션 종료 후 소멸, 패턴은 여기 기록으로 충분). 규칙상 auth!=null이면 quizzes/ 쓰기 가능해서 되는 방법.
- ★S5 지문에 【보기】ㄱㄴㄷㄹ 조합형 — `<보기>` 꺾쇠로 쓰면 innerHTML이 태그로 먹으니 【】 유지할 것.
