## 과목 분리 구조 (다음 퀴즈 추가 시 이대로)
- 퀴즈 객체에 **`subject:'gen'`** 필드만 붙이면 /gen 화면에 감. **없으면 생명과학.**
- 새 퀴즈 추가 경로 2가지: ① admin.html [＋ 새 퀴즈] + 과목 드롭다운(즉시 반영, 코드 수정 없음) ② index.html SEED에 추가 + 배포(없는 퀴즈만 transaction 시드라 기존 DB 안 건드림).
- `subjectOf()`는 관대 판정('Gen'·'유전'·'genetics'도 gen으로 흡수) — 오타로 유전 문항이 생명과학 화면에 새는 것 방지.
- admin의 저장·백업복원·JSON/엑셀 가져오기 전부 subject 보존 패치됨. 엑셀 18번째 열 '과목(subject)' (빈칸=생명과학, gen=생물의 유전, 미지 값은 기존 유지+경고).

### ★조립기를 남겼다 — `생물의 유전/활동/_build_퀴즈1-2.js` (136단언)
지난번(심화 10문항)에는 조립 스크립트를 스크래치패드에 두어 세션과 함께 사라졌다. 이번엔 레포에 둔다.
- `node _build_퀴즈1-2.js` → 검사만 · `--out FILE` → 퀴즈 객체를 JSON으로
- 가계도는 데이터로만 적고 `_pedigree_svg.js`가 그린다. **그림이 문제와 어긋나지 않는지**를
  `impliesRecessive`(Q4 열성 판정 근거) · `excludesXLinkedRecessive`(Q5 X염색체 배제 근거) ·
  `parentsOf`(Q9 경로 1→4→7)로 **다시 확인한다.**
- ★`xmlns="http://www.w3.org/2000/svg"`는 주소가 아니라 이름이므로 「외부 URL 0건」 검사에서 뺀다(여기 걸렸다).
- ★`parentsOf`는 배열이 아니라 `{father, mother}`를 돌려준다(여기도 걸렸다).

### 교사 검토 반영 1건
Q6 ②의 「**한 사람이 가질 수 있는** 유전자형은 6가지」 → 「**사람의 ABO식 혈액형** 유전자형은 6가지」.
한 사람의 유전자형은 하나뿐이고 6가지는 **집단에서 나타날 수 있는 가짓수**다. 해설도 같은 취지로 다듬었다.

### ★RTDB 반영 절차 (이번에 쓴 그대로 — 다음에도 이 순서)
익명 인증(identitytoolkit signUp) → GET `quizzes` 현재 상태 → **`quizBackups/`에 통째로 POST** →
`quizzes/<id>` PUT → `quizMeta/<id>` PUT → GET 재검증.
- ★**「바이트 일치」로 검증하면 안 된다** — RTDB는 키를 알파벳 순으로 돌려주므로 문자열이 달라진다.
  **키를 정렬한 뒤 비교(깊은 비교)** 할 것. 이번에 false가 떠서 놀랐는데 실제로는 일치였다.
- quizMeta 모양은 앱이 쓰는 것과 같게: `{title, subtitle, subject, totalQuestions, questions:[{chapter,q,options,answer,hidden}], updatedAt:{".sv":"timestamp"}}`
  (index.html 698행 · admin `metaFromObj`). 학생이 접속하면 앱이 어차피 다시 써 준다.
