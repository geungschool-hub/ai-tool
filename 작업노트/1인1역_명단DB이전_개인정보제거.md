# 1인1역 앱 — 학생 명단(실명) 소스코드 제거 → RTDB 이전

> 2026-07-13 작업. **중단 지점 있음 — 아래 "지금 상태" 먼저 읽을 것.**

## 왜 하는가

`1p1t.html`의 `STUDENTS` 상수에 **26명 학번+실명+역할**이 하드코딩돼 있었다.
저장소(ai-tool, PUBLIC)뿐 아니라 **배포된 앱 자체가 공개**라 주소만 알면 소스 보기로 전부 읽힌다.
→ 저장소에서만 지워도 소용없고, **클라이언트 소스에서 빼야** 해결된다.

## 설계 결정

- 명단은 RTDB `students/{학번}` = `{num, name, role, dept, desc}` 에 둔다.
- **읽기는 인증 후에만**: 학생=본인 것만, 담임=전체. (규칙으로 강제)
- 입장 화면은 인증 전이라 **번호만 표시**(01~26). 이름·역할은 로그인 후 기록 화면에서.
  - 사용자 선택. 이름을 로그인 전에 띄우려면 명단을 공개 읽기로 열어야 해서 보호가 무의미해짐.
  - 학생은 자기 번호를 알고, PIN이 있어 오입장 위험 없음.

## 함정 메모 (다음에 또 만남)

- **로컬 `database.rules.json`(7/10)은 배포된 적 없는 하드닝 초안이었다.** 라이브와 달리
  `studentMeta/uid` 쓰기에 `config/enrollOpen === true` 게이트가 있는데 **`config` 노드가 아예 없다(null)**.
  그대로 배포했으면 **아직 계정 없는 21명이 로그인 불가**가 됐을 것.
  → 규칙 배포 전엔 **반드시 라이브 규칙을 먼저 읽어서 비교**할 것.
- 라이브 규칙 읽는 법 (CLI에 `rules:get` 명령 없음):
  configstore(`~/.config/configstore/firebase-tools.json`)의 `tokens.refresh_token`
  → 공개 OAuth 클라이언트로 access_token 교환
  → `GET https://<db>.firebasedatabase.app/.settings/rules.json` (Bearer)
- 규칙 검증은 **웹 API 키로 실제 계정 만들어 REST로 읽어보는 게 확실하다**(위 표). 단 흔적(studentMeta) 반드시 삭제.
- `1person1task/`에 `firebase.json`이 없어서 그동안 규칙이 콘솔 수동 관리였다 → 이제 파일로 정본화됨.
