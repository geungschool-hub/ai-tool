# 🔧 활동 기록 — 어디에 남기고 어디에 남기지 않는가 (2026-08-21 신설)

> 인터랙티브 활동에서 **학생이 무엇을 골랐는지·맞혔는지를 남기는 장치**에 관한 정책과 코드 뼈대.

## ★한 줄 원칙

**평가에 쓸 자료가 있는 활동에만 기록한다. 연습 활동에는 넣지 않는다.**

기록은 공짜가 아니다. 남기는 순간 학생 화면에 「첫 번째로 고른 것만 기록된다」 같은 문구가 따라붙고,
그러면 **첫 클릭이 곧 점수**가 되어 학생이 답을 고르기 전에 멈춘다.
연습 활동에서 그 멈춤은 순손실이다 — 어차피 그 자료를 아무 데도 쓰지 않기 때문이다.

| | 기록한다 | 기록하지 않는다 |
|---|---|---|
| **판단 기준** | 수행평가·점수·세특 재료로 **실제로 흘려보낼 곳이 있는가** | 흘려보낼 곳이 없다 |
| **예** | 🧵 단백질합성(수행①) · 🌳 가계도 분석(평가 자료로 설계됨) | 🧬 염색체 비분리(1-3 연습) · 힌트 열람 |
| **화면 표시** | 「첫 시도에 맞힌 N / M」 | 「푼 문항 N / M」 (맞고 틀림을 세지 않는다) |

> ※「기록하지 않는다」가 **저장하지 않는다**는 뜻은 아니다.
> 고른 답(`pPick`)은 **새로고침 복원용으로 반드시 남긴다** — 태블릿 수업에서 날아가면 그게 사고다.
> 남기지 않는 것은 **정오(맞았나 틀렸나)** 다.

## 1. 기록하는 쪽 — 코드 뼈대 (정본: 1-2 가계도 활동)

```js
/* state 에 기록 칸을 둔다 */
function freshState(){
  return {
    pPick:{},        // 고른 번호 — 화면 복원용 (기록 여부와 무관하게 늘 있다)
    first:{},        // ★첫 시도 정오 — 평가 자료. 이 줄이 「기록한다」의 전부다
    ...
  };
}

/* 고를 때: 첫 시도만 남기고, 다시 골라도 덮지 않는다 */
function pick(id, i){
  var key = 'prac.' + id;
  if (state.first[key] === undefined) state.first[key] = (i === answerOf(id));
  state.pPick[id] = i;                    // 화면은 마지막 선택을 따른다
  paint(id); saveState();
}

/* 세기 */
function scoreOf(list){
  var n = 0;
  list.forEach(function(p){ if (state.first['prac.' + p.id] === true) n++; });
  return n;
}
```

### 왜 「첫 시도만」인가
답을 고르면 화면이 **정답을 드러낸다**(옳은 선택지에 `.right`, 나머지에 `.dim`).
그래서 마지막 선택을 세면 다시 골라 전원 만점이 된다 — **첫 시도가 아니면 점수가 아니다.**

### 함께 지켜야 할 것
- **④와 ⑤처럼 묶음이 둘 이상이면 id 가 겹치면 안 된다** — 기록 키가 섞인다. 회귀 검사로 막을 것.
- 잠긴(미개방) 상태의 클릭은 기록되지 않아야 한다.
- 라운드를 되돌려 문항이 다시 잠겨도 **기록 자체는 남긴다**(평가 자료이므로).
- **힌트를 연 것은 기록하지 않는다** — 「누르면 감점」 오해를 없앤다(교사 결정 2026-08-20).
  이건 기록하는 활동에서도 마찬가지다.

### 반출(학번과 함께 내보내기)
아직 붙이지 않았다. 붙일 때 `state.first` 가 그대로 재료가 된다.
🟡 교사 지시로 **1단원 전체를 전개한 뒤로 미뤄 둔 상태**다.

#### 🟡 2026-08-26 — 「정리하기 답안을 나한테 오게 할 수 있나」 (판단 보류)

> 교사: 「앞으로 만들 각 웹활동의 **정리하기에 학생들이 답을 적으면 나한테 오도록** 할 수 있나?
> 아 근데 그러려면 **학생들이 자기 정보를 입력해야 되니까 좀 그런가?**」
> → 같은 날 이어서: 「**세특 재료로 뭔가를 하는 건 좀 더 생각해 볼게.
> 아예 따로 활동을 하나 잡는 게 나을 것 같기도.**」

**결론: 지금은 붙이지 않는다.** 각 활동에 수거 장치를 다는 대신,
**세특 재료를 노리는 활동을 따로 하나 세우는 쪽**을 교사가 검토 중이다.
→ 그때까지 새 활동은 **수거 없이**(localStorage 복원용만) 만든다. 이 문서 §0 원칙 그대로다.

기술적으로는 세 길이 있고, 이미 이 프로젝트 안에 전례가 있다.

| 길 | 무엇 | 개인정보 | 전례 |
|---|---|---|---|
| **A** | 「내 답안 복사하기」 단추 → 클립보드에 학번·이름+답안. 학생이 **이미 쓰는 제출 통로**(클래스룸·패들렛 등)에 붙여 넣는다 | **새로 저장되는 곳 0.** 서버·계정 없음. 학생이 스스로 적어 스스로 낸다 | 없음(가장 가벼움) |
| **B** | Firebase 수집 + 교사용 `admin.html`(비밀번호 게이트) · 실시간 목록 · CSV | 학번·이름이 **외부에 저장된다.** 보안 규칙·보존 기간·학교 방침이 걸린다 | [[보고서작성법_가이드]] · [[융과탐_후속탐구보고서_가이드]] · [[생물의유전_복습퀴즈]](학번·PIN) |
| **C** | 수거 없음(현재). 캡처·인쇄로 낸다 | 0 | 지금 활동 전부 |

★**A 가 권고안이다** — 얻는 것의 대부분을 가져오면서 **앱이 개인정보를 다루지 않는다.**
그리고 A 를 해 두어도 나중에 B 로 올라가는 길이 막히지 않는다.
★**B 가 정말 필요한 경우는 「71명 답안을 통째로 읽어야 할 때」** 다.
그때는 학교 개인정보 처리 방침을 한 번 확인하고 간다.

⚠ 이 판단이 서기 전에 **각 활동에 수거 장치를 달지 말 것.** 달았다 떼는 비용이 크다(위 §2 참조).

## 2. 기록하지 않는 쪽 — 걷어낼 때 손대는 곳

1-3 비분리 활동에서 실제로 걷어낸 자리(2026-08-21). 다른 활동에 적용할 때 이 목록대로 훑으면 된다.

| # | 자리 | 처리 |
|---|------|------|
| 1 | `freshState()` 의 `first:{}` · `wrong:{}` | 칸째로 지운다 |
| 2 | 복원 시 검사 목록 `['roundDone','sumPick','pPick','first','wrong','ta']` | `first`·`wrong` 뺀다 |
| 3 | `pick*()` 안의 `if (state.first[key] === undefined) …` | 지운다 (`var key` 도 미아가 된다) |
| 4 | `scoreOf` · `pracScore` · `pedScore` | 함수째 지운다 |
| 5 | 화면 태그 `0 / 5` | `푼 문항 0 / 5` (id 도 `…Score` → `…Prog` 로 바꿔 뜻을 맞춘다) |
| 6 | 안내 문구 「첫 번째로 고른 것만 기록된다」 | 「몇 번을 다시 골라도 된다 — 고른 답은 기록되지 않는다」 |
| 7 | 완료 문구 「첫 번째 시도에 옳게 답한 것은 N문항」 | 맞힌 수를 빼고 **해설 다시 읽기로** 이끈다 |
| 8 | **쓰기 전용 집계** (예: `state.wrong` 오답 횟수) | 읽는 곳이 없으면 그것도 기록이다 — 함께 지운다 |

### ★옛 저장분 청소 — 빠뜨리기 쉬운 자리
이미 활동을 하던 학생의 브라우저에는 `first`·`wrong` 이 든 blob 이 남아 있다.
1-3 은 복원이 `Object.keys(state)`(= `freshState()` 가 정의한 칸) 만 돌기 때문에
**옛 칸은 복원되지 않고, 한 번 저장하면 저장소에서도 지워진다.**
▷ 복원이 `Object.keys(saved)` 를 도는 구조라면 **옛 기록이 되살아난다.** 옮겨 붙이기 전에 이 방향을 확인할 것.

## 3. 회귀 검사 — 되살아나는 것을 막는다

기록을 걷어낸 활동에는 **없음을 감시하는 검사**를 반드시 붙인다.
정본 = `생물의 유전/활동/_test_염색체비분리.js` 의 **[15] 기록하지 않는다** 절. 통째로 복제해 쓸 것.

검사하는 것: state 에 칸이 없다 · 코드가 그 칸에 쓰지 않는다 · 점수 함수가 없다 ·
저장 blob 에 없다 · **전부 오답이어도 진행 표시가 다 찬다** · 화면 문구에 「맞힌/점수/첫 시도」가 없다 ·
옛 blob 이 청소된다 · 옛 id(`pracScore` 등)가 남아 있지 않다.

### ★검사가 실제로 무는지 변이로 확인할 것
[15]를 붙인 뒤 **일부러 기록을 되살려 넣고 돌려서 FAIL 이 뜨는지** 봤다(4건 FAIL 확인).
안 물면 검사가 아니라 장식이다 — 2026-08-20 에 CSS 회귀를 눈으로도 테스트로도 못 잡은 전례가 있다.
