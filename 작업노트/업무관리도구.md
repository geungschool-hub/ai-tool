## 손대기 전에 알아야 할 것

- **계정 둘** — T(교사)·B(봇). 비밀번호는 교사만 안다. 규칙은 `database.rules.json`(레포에 있다).
- **배포는 호스팅과 규칙이 따로다.** 윈도 node 24 는 `.cmd` 를 못 부르니 `firebase.js` 를 node 로 부른다.
  `node "$APPDATA/npm/node_modules/firebase-tools/lib/bin/firebase.js" deploy --only hosting --project geung-taskboard`
  (규칙은 `--only database`.)
- **검증된 블록 넷**(`PARSE`·`GROUP`·`STORE`·`SYNC`)은 화면을 갈아엎을 때도 건드리지 않는다.
  `localStorage` 는 **STORE 블록 안에서만** 쓴다(테마 `tmTheme`·되돌리기 `tmUndo` 도 거기 있다).
- **문법은 화면에서 칩을 없앤 뒤에도 그대로 산다** — `@담주화` `#교` `!` `+체크` `>id 수정` 을 손으로 치면 먹는다.

## ★두 번 밟은 함정 (PRD §10 에 자세히)

| | |
|---|---|
| 규칙을 실제로 두드려 보지 않은 것 | `log/$id` 가 덧붙이기 전용이라 **되돌리기·삭제가 라이브에서 통째로 반려**되고 있었다. 다중 경로 쓰기는 원자적이다 — 한 경로가 막히면 전부 막힌다 |
| 앵커 없는 `closest('[data-...]')` | `<html data-theme="dark">` 까지 올라가 **설정 ✕ 가 안 먹었다.** `closest('button[data-theme]')` 처럼 앵커를 준다 |
| CSS 특정도 | `.row .meta [data-edit]` 가 `.row .m-area` 를 이겨 PC 화면에 태그가 겹쳤다. 숨김 규칙에도 같은 깊이를 준다 |
| 범위로 지우기 | 캘린더 CSS 를 「A 부터 B 까지」로 지웠더니 사이의 `nav` 규칙이 함께 날아갔다. **지우기 전에 그 구간을 눈으로 볼 것** |

> 검사가 통과해도 라이브에서 안 되는 것이 있다 — **규칙·특정도·배선은 브라우저에서 직접 눌러 봐야 잡힌다.**
> 확장이 안 붙으면 [[chrome-extension-account]] 대로 크롬 계정부터 본다. 창 폭이 안 줄면 **390px iframe** 으로 잰다.
