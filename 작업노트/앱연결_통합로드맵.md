# 앱 연결성 강화 — 통합 로드맵 (2026-07-10 확정)

## ★6단계 배관 (2026-07-26 오후) — 학기말 주제 탐구(보고서·발표) → 생기부. **원본이 파일 42개**

앞선 배관들과 결정적으로 다른 점: **재료가 정형 데이터가 아니라 학생이 낸 파일 뭉치**였다.
hwp·hwpx·docx·pptx·pdf·txt 6종 42개 파일 → 학생 37명 → 재료 36명.

### 파이프라인 (다음 재료도 이 순서 그대로)
1. **인벤토리** — 파일 → 학번 매칭. 키는 파일명의 5자리 sid. ★정규식은 `(?<!\d)(20\d{3})(?!\d)`
   (`\b`는 `20615홍길동`처럼 숫자 뒤에 한글이 바로 붙으면 실패한다 — 이름은 예시).
   sid가 없으면 이름으로, 후보가 1명일 때만 확정.
2. **중복·오분류 정리** — md5로 같은 파일을 걸러낸다(보고서 사본이 발표자료 폴더에 3쌍 있었다).
   폴더가 알려주는 반과 학번이 알려주는 반이 다르면 **학번이 정답**(2건 발생).
3. **추출** — 형식별 추출기(`학기말 주제 발표/_extract.py`). hwp는 OLE+raw deflate(`방법모음_문서추출과판독.md`),
   hwpx·docx·pptx는 zip 안 XML, pdf는 PyMuPDF.
4. **깨짐 검사** ★ — 추출이 '성공'해도 폰트 인코딩이 깨져 본문이 전부 한 글자로 나오는 경우가 있다.
   한글 글자수만 세면 정상처럼 보인다. **최빈 글자 비율**로 판정(정상 3~6% / 깨짐 40%).
5. **판독** — 텍스트가 없는 자료는 페이지를 PNG로 렌더해 눈으로 읽는다.
   ★pptx가 이미지뿐이면 미디어가 조각으로 흩어진다(12장 → 89개) → **PowerPoint COM으로 PDF 변환**(`SaveAs(path, 32)`) 후 렌더.
   ★판독은 **이중 독립 + 코드로 불일치 판정 + 갈린 것만 재판독**(진화 논설문과 같은 구조). 7명 중 5명이 갈렸다.
6. **재료 작성** — 참고자료(주제·질문·근거·결론·산출물 요약) + ev 한 줄.
7. **겹침 제거** ★★ — 아래.
8. **빌드 → 테스트 → 전송 → 전후 대조 검증**.

### ★★같은 탐구의 앞뒤 재료는 ev가 겹친다 — 반드시 재고 다시 쓸 것
계획서(65명)와 주제 탐구(36명)는 **33명이 같은 탐구**다. 그대로 두면 한 학생의 프롬프트에
거의 같은 문장이 두 줄 들어간다. 실제로 11명이 그랬다.
- 토큰 Jaccard(0.30 이상 3명)나 최장 공통 부분열(14자 이상 15명)로는 **놓친다** — 잔가지만 다른 near-duplicate를 못 잡는다.
- **`difflib.SequenceMatcher` 비율**이 정확했다. 0.42 이상을 다시 썼다(0.90·0.80·0.63… 11명).
- 다시 쓰는 방향: 계획서 ev = **계획 단계**(질문 좁히기·주장·논거 설계) / 주제탐구 ev = **계획에 없던 것**
  (실제 자료 처리 방식·구성·계산·확장 질문·인용). 적용 후 최고 0.34 · 중앙값 0.20.

### 규격
| 보내는 것 | 무엇 |
|---|---|
| `paste` | `[학기말 주제 탐구 · 날짜] (학생이 낸 보고서·발표자료를 읽고 정리한 요약)` + 주제·탐구 질문·조사/근거·결론·산출물 (+ 확인 필요) |
| **`ev`** | 학생별 한 줄. 관찰자 시점·명사형 종결·수행과 결과 중심 |
| `rubric` | id `report-pres-2026-1` · grp **`과학 탐구 보고서·발표`** · 점수 없는 항목 1개(`탐구 수행과 발표`) |
| ~~`logs`~~ | 보내지 않음 |

★**보고서와 발표를 한 활동으로 묶었다.** 같은 탐구의 두 산출물이라 나누면 같은 내용의 ev가 두 줄 생긴다.
발표를 했는지는 참고자료 `· 산출물:` 칸에 적는다.

- ★**활동(grp)이 계획서 런처와 다른가** — 계획서 런처를 함께 읽어 grp·id를 실제로 비교한다(같으면 나중 ev가 통째 거부).
- ★**계획서 배관과 나란히 넣어도 서로 덮어쓰지 않는가** — 두 payload를 연달아 병합해 둘 다 남는지 확인(두 재료를 다 가진 학생 33명).
- ★**공동 제출 쌍의 ev가 서로 다른가** + 참고자료에 공동 사실이 적혔는가.

## ★5단계 배관 (2026-07-26 오후) — 보고서 계획서 → 생기부. **재료마다 활동을 갈라 쓴다**

진화 배관이 세운 원칙(점수는 위계로, 내용은 `ev`로)을 **점수가 아예 없는 재료**에 적용한 첫 사례.

### 왜 누가기록을 버렸나 — 실측 두 가지
1. **정보가 0으로 늘었다.** 런처가 만들던 누가기록(주제·질문·주장·논거)은 참고자료 7항목의 **부분집합**이었다
   (전수 대조 누락 **0건**, 게다가 논거는 120자에서 잘린 열화판). `buildUserPrompt`는 둘 다 넣으므로 같은 사실이 두 번 들어갔다.
2. **문틀이 65명 동일했다.** 「탐구 주제 「」로 계획서를 작성하며 … 논거로 … 제시함」.
   혈액형은 *내용*이 같아서 문제였다면 여기선 *뼈대*가 같다. 같은 함정의 다른 층위.
   덤으로 해시가 190KB(실측 상한 200KB)였고, 버리니 **126KB**.

★비문의 원인도 같은 줄이었다 — 학생의 **완결 문장을 명사구 자리에 조사로 붙였다**(`…차 있다 를 제시함.` 65/65).
자동 문장 생성이 학생 원문을 삼킬 때는 **조사·어미로 잇지 말고 라벨(`· 주제:`)로 나열**하거나, 아예 사람이 한 줄을 쓴다.

### 규격
| 보내는 것 | 무엇 | 왜 |
|---|---|---|
| `paste` | 계획서 7항목 전문 + 머리말 `(계획 단계 — 실행·결론 아님)` | 교사가 읽을 근거. 머리말이 없으면 AI가 **하지도 않은 실험을 수행한 것처럼** 쓴다 |
| **`ev`** | 학생별 한 줄(관찰자 시점·명사형 종결·계획 단계만) | ★개인화. 프롬프트가 '핵심 재료·반드시 반영'으로 못박은 유일한 슬롯 |
| `rubric` | id `report-plan-2026-1` · grp `과학 탐구 보고서 계획서` · **점수 없는 항목 1개** | ev를 띄우기 위한 최소 구성(아래) |
| ~~`logs`~~ | **보내지 않음** | 위 두 가지 이유 |

★**항목이 없으면 `ev`는 조용히 사라진다.** `ev`는 `rubric.grp`를 키로 저장되지만(`index.html:2386`),
`evBlocks`(1326)는 **그 grp를 가진 항목이 `items`에 있을 때만** 프롬프트에 찍는다. 점수가 없어도 항목 1개는 반드시 함께 보낼 것.
활동 이름은 `normItem`(656)이 grp를 `base`로 승격시켜 그대로 보인다.

★★**grp는 재료마다 다르게.** 앱은 이미 있는 ev를 **절대 덮어쓰지 않는다**(`evKeep`).
계획서·보고서·주제발표를 같은 활동 이름으로 보내면 **나중 ev가 통째로 거부**된다. 배분표 = `세특_재료지도.md`.

## ★4단계 배관 완성 (2026-07-26) — 진화 논설문 → 생기부. **점수는 위계로, 내용은 `ev`로**

이 문서 아래쪽(3단계 끝)에서 예고한 **"점수만으로 문장을 만들면 동일 문장이 된다 → 개인화는 `ev`로 풀 것"** 을 실제로 구현했다.

### 왜 이 구조인가 — 혈액형에서 배운 것
혈액형 배관이 넣은 **누가기록 89건을 이날 걷어냈다.** 점수를 기계적으로 문장화한 것이라
**점수가 같은 학생은 문장이 글자 하나까지 같았고**, 위계 levels와 정보가 100% 겹쳤다.
그런데 `buildUserPrompt`가 `[누가기록]`으로 AI에 넣기 때문에 **재료가 전부 정형** → 초안이 반 전체에서 비슷해진다.
→ **진화는 정반대다.** 학생마다 사례·분야·수치가 전부 달라 그 내용이 유일한 개인화 재료다.

| 보내는 것 | 무엇 | 왜 |
|---|---|---|
| `levels` | 채점 a1~a4 → 위계 수준 | 정량 뼈대. 수준별 문장의 입력 |
| **`ev`** | 학생별 특이사항 한 줄 | ★**개인화**. 합성·AI 프롬프트 양쪽에 반영되는 유일한 슬롯 |
| `paste` | 판독 상세(사례·영향) | 교사가 읽을 근거 |
| ~~`logs`~~ | **보내지 않음** | `paste`와 겹쳐 프롬프트만 정형화된다(위 교훈) |

### ★수신부 확장 2 — 여러 반을 한 번에 받는다 (`groups`, 앱 v3.10)
**"왜 반별로 4번 클릭이냐"(사용자)** → 클릭 수가 문제가 아니라 **수칙이 위험했다.**
반마다 탭을 열면 각 탭이 부팅 때 상태를 한 번만 읽고 저장 때 통째로 덮어쓰므로,
탭을 쌓는 순간 앞 반 병합이 날아간다. 그래서 '한 번에 한 반, 탭 닫고 다음'이라는 지키기 어려운 수칙이 붙어 있었다.
- payload에 **`groups:[{className,students}]`** 추가. `rubric`·`area`·`source`는 공유. 구버전(`className`+`students`)은 **동작 불변**.
- 한 탭·**확인 한 번**·**저장 한 번**·스냅샷 한 개 → 덮어쓰기 사고가 원천적으로 없다.
- ★**여러 반 모드에서는 폴백 금지.** 없는 반이 섞이면 **통째로 중단**한다(단일 반일 때만 빨간 모달로 현재 반 폴백 허용).
  4개 반을 보내다 하나가 안 맞는다고 현재 반에 쏟아부으면 서로 다른 반 기록이 한 반에 뒤섞인다.
- 같은 반 중복도 중단. 건너뛴 학생·동명이인 보고에는 `[반 이름]`이 붙는다.
- 확인창에 **반별 인원이 미리** 보인다(`· 생명과학 A — 25명`) → 보내기 전에 틀린 걸 잡는다.
- **URL 길이 실측**: 4개 반 합쳐 약 **102KB**. Chrome 헤드리스로 재 보니 **해시 200KB까지 정상 이동**한다.
  (주소창 붙여넣기만 한계가 있고 `window.open` 이동은 문제없다 — 예전 노트의 60KB 우려는 붙여넣기 얘기였다.)
- 검증: `_test\test_groups.js` **11건 신설** + `test_send_evo.js`에 2건 추가 → 전체 **149건 green**.
  ★그중 하나가 **"한 번에 보내기와 반별로 보내기의 결과가 같다"**(state 전체 문자열 비교)이고,
  또 하나는 **담임반을 열어 둔 채 보내도 담임반이 오염되지 않는가**이다.

### 수신부 확장 — `importRecords`가 `ev`를 받는다 (앱 v3.9)
- 활동 키 = payload의 `rubric.grp` (`gkeyOf`와 같은 키 공간) → 위계 항목과 같은 활동에 붙는다.
- ★**교사가 이미 적어 둔 특이사항은 절대 덮어쓰지 않는다**(문장 씨앗과 같은 원칙). 덮으면 손으로 쓴 관찰이 사라진다.
  같은 내용 재전송은 dup으로 건너뛰고, 다른 내용이 이미 있으면 `evKeep`으로 보고만 한다.
- `rubric`이 없거나 `rubric.grp`가 없으면 `ev`를 **무시**한다(붙일 활동이 없으므로).
- 구버전 payload(ev 없음) 동작 불변 — R1 회귀 통과.

### 송신부 — `생기부_통합\_send_evo_web.html` (gitignore·실명 포함)
빌드 = `_send_evo_web.template.html` + `_build_send_evo.py`. **템플릿 분리 필수**(셸 heredoc으로 JS를 만들면 따옴표가 깨진다).
- 루브릭 `evo-essay-2026-1` / 활동명 `진화론 논설문` / 항목 a1~a4, 점수 **1·3·5 → 수준 2·6·10**
- 문장 씨앗은 관찰자 시점·명사형 종결, **최하 밴드도 부정 서술 금지**
- 반별 버튼 + **미리보기(보내지 않음)** 버튼 — 해시 크기와 첫 학생 샘플을 눌러 볼 수 있다
- 학생 키 = **학번**(원반×100+번호) → 이름 매칭에 기대지 않는다. 이름 오독의 영향을 안 받는 게 핵심

### 검증 — `_test\test_send_evo.js` 13건 (전체 136건 통과)
런처의 `<script>`를 **그대로 실행**해 실제 `build()`로 payload를 만들고, 그걸 **앱의 진짜 `importRecords`에 통과**시킨다.
- end-to-end 4개 반 **90명 병합·건너뜀 0·동명이인 0·이름충돌 0**
- **수준 값 전수 재계산 대조**(약 360건) — 점수에서 정확히 파생됐는지
- `ev` 90건이 **서로 전부 다름**(중복 0) · 활동명·금칙 소재 없음 · **명사형 종결**
- 재전송해도 항목·참고자료·ev 복제 없음
- ★테스트가 실제로 잡은 것: `듦.`은 **ㄻ받침이라 `endsNominal`이 명사형으로 인정하지 않는다**(8건 → `제시함.`으로 교체).
  글자를 나열해 검사하지 말고 **앱의 `endsNominal`을 그대로 호출**할 것.
