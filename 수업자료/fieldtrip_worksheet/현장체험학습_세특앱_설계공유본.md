# 현장체험학습 설문·세특 생성 앱 (FieldNote) — 설계 공유본

> 이 문서는 다른 학교/다른 선생님이 **Claude Code로 같은 앱을 새로 만들 때 참고하는 설계서**입니다.
> 2026학년도 고2 현장체험학습(학생 180명, 12개 진로 계열)에서 실제 운영을 완료한 시스템의 설계와 운영 경험을 정리했습니다.
> 학교별 데이터(계열·체험처·날짜·문항)는 예시이므로 자기 학교에 맞게 교체하면 됩니다.

---

## 1. 앱이 하는 일 (전체 흐름)

```
체험 당일: 학생이 스마트폰으로 QR 접속 → 6자리 코드 로그인 → 9문항 서술형 설문 응답
   (마감일 자정까지 수정 가능, 이후 자동 잠금)
        ↓
교사가 일괄 생성 실행 → Claude API가 학생 답변만을 근거로 세특 초안 생성
   (계열별 고정 템플릿 + 학생 답변 삽입 = "하이브리드 템플릿 채우기")
        ↓
인솔교사: 좌(원답변)/우(초안) 분할 화면에서 검토 → 인라인 수정 → 확정
        ↓
엑셀 내보내기 → (필요시 엑셀에서 수정 후 재업로드) → 담임교사가 반별 조회 → NEIS 붙여넣기
```

핵심 가치 2가지:
1. **AI는 학생 답변에 없는 내용을 절대 지어내지 않는다** — 답변이 부실하면 부실한 세특이 나온다.
2. **학생은 세특의 존재 자체를 모른다** — 학생 화면에 AI·세특 관련 문구 일절 금지(공정성 문제).

## 2. 기술 스택 / 배포

| 항목 | 값 |
|------|-----|
| 프레임워크 | Next.js (App Router) + React + TypeScript |
| DB | Supabase (Postgres) — 무료 플랜으로 충분 |
| AI | Anthropic API (Claude Sonnet 계열, 프롬프트 캐싱 적용) |
| 엑셀 | xlsx 라이브러리 |
| 배포 | Vercel (무료), 학생은 QR로 접속 |
| 인증 | 자체 JWT (학생: 6자리 코드, 교사: 공용 비밀번호) — Supabase Auth 미사용 |

⚠️ **Next.js 최신 버전은 Claude의 학습 데이터와 다를 수 있음.** 프로젝트 생성 후 `node_modules/next/dist/docs/`의 문서를 먼저 읽으라고 Claude Code에게 지시할 것. (프로젝트 루트 CLAUDE.md에 그 지시를 박아두면 편함.)

## 3. 역할·권한 정책 (변경 불가 전제)

세특은 교사가 작성하는 공식 학교 기록이므로, AI 결과물을 학생이 사전 열람하면 공정성·입시 문제가 됨.

| 역할 | 볼 수 있는 것 | 볼 수 없는 것 |
|------|-------------|-------------|
| **학생** | 자신의 설문 답변만 | AI 초안, 확정본, 타 학생 정보 일체 |
| **인솔교사** | 담당 계열 학생의 답변+초안+확정본 | 다른 계열 |
| **담임교사** | 담당 반 학생의 **최종본만** | 원답변, AI 초안, 다른 반 |
| **관리자** | 전체 | — |

구현 규칙:
- 학생 JWT로 세특 관련 API(`/api/sect/**`) 호출 시 **미들웨어 레벨에서 403** (라우트 핸들러 도달 전 차단).
- 학생 화면에 "AI 분석 중", "선생님 검토 중" 등 **암시적 표현도 금지**. 학생이 보는 마지막 화면은 "답변 저장 완료"뿐.
- AI 생성은 **교사가 수동 트리거** (제출 즉시 자동 생성 금지).
- 교사 계정은 **공용 1개** (비밀번호 공유). 로그인 후 역할 선택(인솔/담임) → 계열 또는 반 선택 → JWT에 스코프(`scoped_track_ids` / `scoped_class`) 포함 → 이후 모든 조회 자동 필터.

## 4. 설문 9문항 (필수 6 + 선택 3)

| # | 평가 요소 | 필수 | 질문 요지 |
|---|-----------|------|-----------|
| 1 | 전공역량 | ✅ | 희망 계열/학과 + 오전 대학 탐방에서 알게 된 '전공자의 핵심 자질' |
| 2 | 활동 핵심 정리 | ✅ | 오늘 체험 전체를 한 문장으로 정의 |
| 3 | 심화 관찰 | ✅ | 오후 체험처에서 진로와 연결해 가장 흥미로웠던 지점 |
| 4 | 탐구 확장 | ✅ | 더 공부하고 싶어진 주제·도서·후속 탐구 계획 |
| 5 | 성장 기록 | ✅ | 진로 확신 또는 새로운 고민 |
| 6 | 자기 주도적 로드맵 | ✅ | 남은 고교 생활 동안 보완할 학업 역량·활동 계획 |
| 7 | 융합적 사고 | 선택 | 교과 이론이 현장에서 적용되는 것을 발견한 사례 |
| 8 | 문제 해결 | 선택 | 해당 분야 전문가들의 사회적 고민·기술적 한계 |
| 9 | 직업 윤리 | 선택 | 미래 직업인으로서 지켜야 할 윤리·가치 |

설계 의도: **문항 = 세특 문단의 재료**. Q1→문단1, Q2+Q3→문단2, Q4+Q5+Q6→문단3, Q7은 50자 이상+특성이 드러날 때만 문단3에 보너스로 추가. **Q8·Q9는 세특 본문에 사용하지 않음**(참고용). 문항을 바꿀 때도 이 매핑 구조를 먼저 정하고 문항을 짜는 것을 권장.

## 5. 세특 생성 로직 (핵심 설계)

### 하이브리드 템플릿 채우기
- **공통 골격**: 계열별 고정 템플릿을 DB에 사전 등록 → AI가 변경 불가
- **개별 삽입부** `[대괄호]` 슬롯: AI가 학생 답변에서 추출한 내용만 채움

3문단 템플릿 예시 (사회과학계열, 실제 운영본):
```
문단1: 오전 대학 탐방에서 멘토와의 질의응답을 통해 [학과명] 진학에 대한 이해도를
       높이고 핵심 자질로서 [핵심 자질] 함양에 대한 열의를 다짐.
문단2: 오후 계열별 체험 장소인 [체험처]을 방문하여 [실무 과정] 관찰함.
       특히 [흥미 지점]을 통해 [깨달음] 깨달음을 얻음.
문단3: 현장체험학습 이후, [관심 주제]에 관심을 갖게 되어 [탐구 계획]을 탐구해보고자 함.
       또한 [다짐]을 실천하기로 다짐함.
```
- MVP는 대표 계열 템플릿 1개만 등록하고, 미등록 계열은 AI가 같은 패턴을 계열·답변 어휘에 맞게 자동 변주 → 실운영에서 충분히 통했음.

### Hard Constraints (시스템 프롬프트 최상위 원칙)
1. **오직 학생 답변만 근거로 작성.** 외부 지식·일반론·격려·추측·과장 금지.
2. 답변에 없는 사실·활동·감정·다짐 절대 생성 금지.
3. 답변이 부실하면 부실한 세특 그대로 도출. 분량 채우기용 미사여구 금지.
4. **분량: 850~900 Byte 목표, 900 절대 초과 금지** (NEIS 관행: 한글 1자=2B, 영문/숫자/공백=1B). 미달은 허용.
5. **문체: 평어체(음슴체)** `~함/~임/~음` 종결, 주어 생략.
6. **금지 표현**: 지역명·대회명·기관/기업/학원명·수상실적·어학점수·논문·가족정보·성적 → 삭제 또는 일반화. 학과명과 보통명사화된 개념(주민 참여예산제, 탄소중립 등)은 허용.

### 고유명사 일반화 (금지어 대응의 핵심 장치)
체험처마다 "일반화 표현"을 DB에 사전 등록해 프롬프트에 치환 맵으로 주입.
예: 서울시청 → "해설사가 있는 시청 건물" / 국립현대미술관 → "국립미술관" / 서울대학교병원 의학박물관 → "대학병원 의학박물관"

### 답변 품질 플래그 (Q1~Q6)
- `SUFFICIENT`: 50자 이상 + 평가요소 일치 + 구체적 사례
- `INSUFFICIENT`: 20자 미만 또는 불일치 또는 반복
- `EMPTY`: 미응답 또는 "없음"/"모름"
- 하나라도 INSUFFICIENT/EMPTY면 교사 화면 세특 카드에 **근거 부족 경고 배지**.

### AI 출력 형식 (JSON 강제)
```json
{
  "draft": "세특 본문 (평어체, 900B 이하)",
  "byte_length": 876,
  "paragraphs": [{"index": 1, "content": "...", "based_on": [1]}],
  "answer_quality": {"q1": {"flag": "SUFFICIENT", "evidence_snippet": "..."}},
  "guardrail_check": {
    "forbidden_proper_nouns": [], "byte_within_limit": true,
    "style_compliant": true, "fabrication_detected": false
  },
  "warnings": []
}
```
- `paragraphs[].based_on`으로 각 문단이 어떤 답변에 근거했는지 추적 → 서버 후처리에서 매핑 안 되는 문장은 fabrication으로 표시.
- 시스템 프롬프트에 Few-shot 예시 1개(입력 답변 → 출력 JSON) 포함 — 품질에 크게 기여.
- 개인정보 보호: API 호출 시 이름·학번을 **익명 ID(`STU_001`)로 치환**, 응답 수신 후 서버에서 재매핑.
- 비용 통제: 학생당 재생성 최대 5회, 시스템 프롬프트 캐싱, 토큰 사용량 DB 로깅. **실비용: 학생 180명 기준 총 $5~10 수준.**

## 6. DB 스키마 (Postgres, 실제 운영본 그대로)

```sql
create table users (        -- 계정 (교사/관리자용, 학생은 별도)
  id uuid primary key default uuid_generate_v4(),
  email text not null unique,
  role text not null check (role in ('student','teacher','admin')),
  created_at timestamptz not null default now()
);

create table tracks (       -- 진로 계열 (12개)
  id uuid primary key default uuid_generate_v4(),
  code text not null unique,             -- 예: SOC_SCI
  name text not null,                    -- 예: 사회과학
  morning_university text not null,      -- 오전 탐방 대학
  afternoon_venue_description text not null default '',
  has_template boolean not null default false,
  created_at timestamptz not null default now()
);

create table visit_sites (  -- 체험처 고유명사 → 일반화 표현
  id uuid primary key default uuid_generate_v4(),
  track_id uuid not null references tracks(id) on delete cascade,
  original_name text not null,
  generalized_name text not null,
  type text not null check (type in ('morning','afternoon')),
  created_at timestamptz not null default now()
);

create table students (
  id uuid primary key default uuid_generate_v4(),
  anon_id text not null unique,          -- STU_001 (API 호출용 익명 ID)
  name text not null,                    -- ※명렬 사전등록 방식에선 nullable로 변경
  student_number text not null unique,
  grade int not null default 2,
  class_number int not null check (class_number between 1 and 7),  -- ★반 수에 맞게 수정
  student_seq int not null,
  access_code text not null unique,      -- 6자리 로그인 코드
  track_id uuid not null references tracks(id),
  created_at timestamptz not null default now()
);

create table survey_questions (
  id uuid primary key default uuid_generate_v4(),
  question_number int not null unique check (question_number between 1 and 9),
  evaluation_element text not null,
  question_text text not null,
  is_required boolean not null default true,
  updated_at timestamptz not null default now()
);

create table survey_answers (
  id uuid primary key default uuid_generate_v4(),
  student_id uuid not null references students(id) on delete cascade,
  question_number int not null check (question_number between 1 and 9),
  answer_text text not null default '',
  is_locked boolean not null default false,
  last_modified_at timestamptz not null default now(),
  locked_at timestamptz,
  unique (student_id, question_number)
);

create table sect_templates (            -- 계열별 3문단 골격
  id uuid primary key default uuid_generate_v4(),
  track_id uuid not null references tracks(id) on delete cascade,
  paragraph1_template text not null,
  paragraph2_template text not null,
  paragraph3_template text not null,
  is_active boolean not null default true,
  updated_at timestamptz not null default now(),
  unique (track_id)
);

create table sect_drafts (               -- AI 초안 (버전 누적)
  id uuid primary key default uuid_generate_v4(),
  student_id uuid not null references students(id) on delete cascade,
  version int not null default 1,
  draft_text text not null,
  byte_length int not null,
  paragraphs jsonb not null default '[]',
  answer_quality jsonb not null default '{}',
  guardrail_check jsonb not null default '{}',
  warnings jsonb not null default '[]',
  tokens_input int not null default 0,
  tokens_output int not null default 0,
  generated_at timestamptz not null default now()
);

create table sect_finals (               -- 확정본 (학생당 1개)
  id uuid primary key default uuid_generate_v4(),
  student_id uuid not null references students(id) on delete cascade unique,
  draft_id uuid references sect_drafts(id),
  final_text text not null,
  byte_length int not null,
  is_locked boolean not null default false,
  confirmed_by text,
  confirmed_at timestamptz
);

create table regen_counts (              -- 재생성 횟수 (학생당 최대 5회)
  id uuid primary key default uuid_generate_v4(),
  student_id uuid not null references students(id) on delete cascade unique,
  count int not null default 0,
  updated_at timestamptz not null default now()
);

create table token_logs (                -- API 비용 추적
  id uuid primary key default uuid_generate_v4(),
  draft_id uuid references sect_drafts(id) on delete set null,
  model text not null,
  tokens_input int not null,
  tokens_output int not null,
  cost_usd numeric(10,6) not null default 0,
  created_at timestamptz not null default now()
);

create table audit_logs (                -- 감사 로그 (원문 답변은 미포함)
  id uuid primary key default uuid_generate_v4(),
  event_type text not null,
  actor_id text not null,
  actor_role text not null,
  target_anon_id text not null default '',
  metadata jsonb not null default '{}',
  created_at timestamptz not null default now()
);
```

운영 중 개선한 것 — **명렬 사전등록 방식**: 학생 `name`을 nullable로 두고 학번·코드만 사전 등록 → 학생이 첫 로그인 때 자기 이름을 직접 기입. 명단 엑셀에서 실명을 옮기는 작업이 줄고, 이름 오타 책임이 학생 본인에게 감.

## 7. 라우트 구조 (실제 파일 트리)

```
src/app/
  page.tsx                    ← 진입 (학생 코드 로그인 / 교사 로그인)
  student/page.tsx            ← 학생 설문 응답
  teacher/scope/page.tsx      ← 역할·계열/반 선택
  teacher/review/page.tsx     ← 인솔교사 검토 (좌 원답변 / 우 초안 분할)
  teacher/homeroom/page.tsx   ← 담임교사 반별 최종본 조회
  api/
    auth/student-login, teacher-login, teacher-scope
    survey/questions, answers, submit
    sect/students, draft, generate, autosave, confirm
    homeroom/students, student-name, track, export
    tracks (+ tracks/public), teacher/reset-pin
src/lib/
  survey-period.ts            ← 응답 기간(마감 자동 잠금) 정의
  byte-counter.ts             ← NEIS 바이트 계산 (한글 2B)
  auth/ (jwt, pin, guards)    ← 학생 3회 오입력 시 5분 잠금
  anthropic/ (client, prompts)
  supabase/ (server, client)
```

주요 UX 사항:
- 학생 설문: 문항당 1화면, 실시간 글자 수, **30초 자동 임시저장**, 필수 미입력 시 제출 비활성화, 모바일 우선(버튼 44px+, 폰트 16px+).
- 교사 검토: 세특 바이트 실시간 카운터, 인라인 편집, 문단별/전체 재생성, 잔여 재생성 횟수 표시, 확정 시 잠금.
- 확정 후 수정은 **엑셀에서** 하고 재업로드하는 흐름 (인앱 재편집 없음 — 단순함 유지).

## 9. 실운영에서 배운 것 (함정 목록 — 꼭 읽으세요)

1. **무료 Supabase는 약 1주 미사용 시 자동 일시정지**되고, DNS까지 내려가서 앱이 통째로 죽은 것처럼 보임(페이지는 뜨는데 데이터만 전부 실패). 운영 기간엔 주 1회 이상 접속하고, 행사 끝나면 **백업부터 받고** 잠들게 둘 것. 정지 후 ~90일이면 프로젝트가 삭제될 수 있음.
2. **백업 스크립트를 먼저 만들 것.** 전 테이블을 JSON 1개로 덤프하는 Node 스크립트(`scripts/backup-survey.mjs` 같은 것)를 운영 시작 전에 준비. 복원 스크립트도 같이 만들어두면 더 좋음(우리는 백업만 만들었다가 아쉬웠음).
3. **데이터 자동 파기 기능은 만들지 말 것.** 처음 PRD엔 기간 만료 자동 삭제가 있었으나 운영해보니 위험해서 폐기 — 삭제는 운영자가 명시적으로 지시할 때만 수동으로.
4. 백업 JSON엔 **학생 실명·학번·서술형 답변이 통째로 들어감** → git에 절대 커밋 금지(.gitignore 필수), 안전한 매체에 2차 사본.
5. **바이트 카운터는 앱 자체 구현** 필요 (한글 2B 규칙은 encodeURI나 UTF-8 바이트와 다름). 교사 화면에 실시간 표시하면 검토가 빨라짐.
6. 학생 이름 null(한 번도 로그인 안 함), 등록만 하고 무응답 등 **미참여 유형이 반드시 나옴** (우리는 180명 중 20명). 대시보드에서 "미등록/무응답/미확정"을 구분해 보여주면 마감 관리가 쉬움.
7. Next.js 최신 버전 함정: 프로젝트 루트에 `CLAUDE.md`를 만들어 "코드 작성 전 `node_modules/next/dist/docs/` 문서를 먼저 읽어라"라고 박아둘 것.

**2026년 운영 실적 참고**: 180명 중 168명 등록, 160명 응답 → **응답자 160명 전원 세특 확정 완료**. 확정본 평균 752B.
