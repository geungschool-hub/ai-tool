## 왜 만들었나
2026-09-11 교사: 「2-1 이 코돈표+전사+번역이라 내용이 엄청 뚱뚱하다. **중심원리~유전부호와 유전정보의 해독** 쪽을
웹활동으로 바꾸고 싶다. 중심원리에 **mRNA·tRNA·rRNA 를 함께** 설명하고 싶다(교과서엔 뒤쪽이지만 앞이 맞다).
중심적인 부분은 **62쪽 해 보기를 충실하게** 따랐으면 좋겠다.」
→ 소단원의 **앞쪽 절반을 수업 자체를 대신하는 활동**으로 옮겼다. 전사 기작(프로모터·RNA 중합효소)은 **넣지 않기로 교사가 확정**했다.

## 무엇을 하는 활동인가
① 4글자로 20종류(4¹·4²·4³ 막대) → ② 중심원리 흐름도 + **61쪽 그림 Ⅱ-2 를 5국면 연출**로 보이고 RNA 3종을 역할 자리에 놓기
→ ③ 코돈표에서 **종결코돈 3 → 개시코돈 → 류신 코돈 6** 찾아 탭(중복성을 스스로 센다)
→ ④ **읽기틀 3개를 갈아 가며 코돈표에서 찾아 탭해 해독** → ⑤ 10·12·17번 치환을 **먼저 예상한 뒤** 확인
→ 💪 선택형 4 · ⑥ 서술 3 + 창의력 1 + 자기평가 3줄.

## ★이 활동의 심장 — 읽기틀을 학생이 가려낸다
62쪽 자료는 **조각**이라 개시코돈이 보이지 않는다. 교사용 교과서의 2번 해답이 곧 활동의 급소다 —
「두 번째·세 번째 뉴클레오타이드에서 시작하면 **중간에 종결코돈이 생기므로**, 코돈은 첫 번째 뉴클레오타이드에서 시작된다.」
그래서 앱은 읽기틀을 **고르게** 하고, 세 틀의 결과를 표에 나란히 쌓아 스스로 배제하게 한다.
61쪽 그림 Ⅱ-2 를 ②의 보기로 먼저 보인 것도 이 대비를 세우기 위해서다(**61쪽은 개시코돈이 보이니 거기서 읽는다**).

## ★앱이 아미노산을 먼저 말하지 않는다
성취기준 02-02 가 「유전 부호 표를 **사용하여** 해독」이다. protein-sim 초판이 검토에서 「중대」로 지목된 자리를 되풀이하지 않았다.
- 「지금 해독할 코돈」에는 **코돈 글자만** 둔다. 대신 **세 축 읽는 길**을 알려 준다.
- **코돈표 칸을 미리 강조하지 않는다** — 칸에 코돈이 병기돼 있어 강조가 곧 정답 공개다. 해독 뒤에만 `.cur`.
- 종결·개시 칸에 **색을 칠하지 않는다**(교과서 표에도 색이 없다). ③의 찾기 과제가 색만 보고 끝나 버린다.
- 탈출구는 **[💡 이 코돈만 확인하기] 하나**뿐이고 `state.hintCodon` 은 **단수**다. 오답 피드백은 읽는 길만 알려 준다.

## 교과서에서 복원한 값 (PDF 좌표로 확정 · 검사가 문다)
```
62쪽 해 보기  5′- CAUGGUAACGUGACUUCGAAUGCA -3′   (24 염기)
  1번째부터  CAU GGU AAC GUG ACU UCG AAU GCA → 히스티딘-글라이신-아스파라진-발린-트레오닌-세린-아스파라진-알라닌 (종결 없음)
  2번째부터  AUG GUA ACG UGA …               → 4번째 코돈이 종결코돈 (아미노산 3개)
  3번째부터  UGG UAA …                       → 2번째 코돈이 종결코돈 (아미노산 1개)
61쪽 그림 Ⅱ-2  주형 3′-ACCTACAACCGTCAT-5′ → mRNA 5′-UGGAUGUUGGCAGUA-3′ (개시 4번째) → 메싸이오닌-류신-알라닌-발린
```
| 치환 | 코돈 | 결과 |
|---|---|---|
| **10번 G→A** (교과서 문항) | GUG → AUG | 발린 → **메싸이오닌** |
| 12번 G→A (보탬) | GUG → GUA | **서열 불변** — 중복성 |
| 17번 C→A (보탬) | UCG → UAG | **아미노산 5개**에서 종결 |
★12·17번은 교과서에 없다. 「같은 한 염기 치환인데 결과가 셋으로 갈린다」를 세우려고 **같은 서열 위에서** 고른 자리다.
`MUTS` 에 손으로 적은 `kind` 가 계산 결과와 맞는지 검사가 문다.

### 브라우저 실측에서 잡은 3건 (헤드리스로는 안 잡힌다)
| 무엇 | 왜 |
|---|---|
| 코돈표 `min-width` **880 → 660px** | protein-sim 에서 물려받은 880px 이 왼쪽 칸(784px)을 넘겨 **넓은 화면에서도 늘 가로 스크롤**이었다. 학생이 탭해야 하는 표인데 오른쪽 G 열이 잘렸다. 자연 폭을 재니 642px 이었다 |
| 좁은 화면 `.pane-l,.pr-do,.pr-q{min-width:0;**width:100%**}` | `min-width:0` 만으로는 부족했다. 세로 flex 에서 가로는 **교차축**이라 `align-items:stretch` 가 「줄의 크기」를 따르는데, 줄은 가장 넓은 항목(660px 표)을 따라 커진다 → 칸이 카드 밖으로 빠져나갔다 |
| 개시코돈을 ↑ 로 가리키던 것 → **세 칸을 테두리로 묶기** | 글 앞의 ↑ 는 4번째 염기가 아니라 **줄 맨 앞**을 가리켰다 |

### 회귀 검사가 잡아낸 본체 결함 2건 (2026-09-11 · 같은 날 고침)
> ★둘 다 **검사를 별도 맥락에서 썼기 때문에** 나왔다. 본체를 쓴 자리에서 이어 썼다면 「방금 이렇게 짰으니까」로 넘어갔을 자리다.

| 결함 | 뿌리 | 무엇이 망가졌나 |
|---|---|---|
| A. 처음 온 학생에게 **읽기틀이 이미 골라져 있었다** | `Number(null) === 0` | 그 틀이 곧 해 보기 2의 **답**이라 고르는 일이 활동에서 사라진다. 「먼저 읽기틀을 고르시오」 가드도 죽은 가지가 됐다 |
| B. `frame`·`codeLast`·`hintCodon`·`mutNow` 가 **복원되지 않았다** | **`typeof null === 'object'`** | 초기값이 null 인 칸이 객체 칸으로 분류돼 저장된 숫자·문자열이 버려졌다. `decN` 같은 진짜 객체 칸만 복원돼 **어긋난 화면**이 됐다 |

★**B 는 메셀슨·스탈 활동에도 같은 모양으로 남아 있을 수 있다**(`balLast`·`repLast` 가 null 초기값이다). 확인해 볼 것.

## 함정
- 코돈표 AUG 칸에 교과서대로 `(개시코돈)` 이 인쇄돼 있어 ③의 **개시코돈 찾기는 글자로 답이 보인다.**
  색칠 금지는 지켰고, 교과서 62쪽 표가 그렇게 표시하므로 그대로 두었다. 바꿀지는 교사 판단.
- 조사는 `을(를)` 로 나란히 적지 않는다 — `hasJong()`/`jo()` 로 골라 쓴다.
- 코돈표는 **③·④ 두 벌**을 같은 함수(`renderCodonTable(boxId, pfx, fn)`)로 그린다. 칸 id 는 `c3_XXX`/`c4_XXX`.
- ④ 를 되돌리면 **⑤ 도 함께 지운다** — ⑤ 는 「1번째 염기부터 읽는다」 위에서만 뜻이 있는 결과다.
