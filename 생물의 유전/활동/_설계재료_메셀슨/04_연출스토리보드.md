## 0. 이 활동이 눈으로 증명해야 하는 것 (설계의 축)

교사 요구를 그대로 옮기면 두 가지다.

1. **질량·밀도 차이가 띠를 만든다** — <sup>14</sup>N-<sup>14</sup>N / <sup>14</sup>N-<sup>15</sup>N / <sup>15</sup>N-<sup>15</sup>N 세 조합이 각각 어느 높이에 앉는가.
2. **왜 분산적·보존적이 아닌가** — 교사용 46쪽 배제 논리 전문:
   - 보존적: 1세대에서 「무거운 띠 + 가벼운 띠가 **같은 두께**」로 나와야 하는데 중간 무게 띠 하나가 나왔다.
   - 분산적: 2세대에서 「중간 무게 띠만」 나와야 하는데 가벼운 띠와 중간 띠가 **비슷하게** 나왔다.
   - 따라서 **1회 복제만으로는 분산적을 지울 수 없다**. 이 「한 번으로는 못 가른다」가 논리의 심장이다.

★이 두 가지를 하나의 시각 문법으로 묶는다.

| 시각 요소 | 뜻하는 것 | 어디서 정해지는가 |
|---|---|---|
| **띠의 색 구성**(세로 4칸 분할) | 그 DNA의 <sup>15</sup>N 비율 | 분자 그림의 칸 색 |
| **띠의 높이** | 밀도 | 색 구성에서 계산 — `y = 34 + 60 × f15` |
| **띠의 굵기·진하기** | 그 무게의 DNA가 전체 중 몇 분율인가 | 분자 개수 비 |

이 세 줄이 다섯 무대를 관통한다. 무대 2에서 규칙을 가르치고, 무대 3에서 분자를 세고, 무대 4에서 띠로 옮기고, 무대 5에서 맞춰 본다.

## 1. 색 규약 — 활동 전체에서 이 두 색만 쓴다

프로젝트 공통 변수에서 고른다.

```css
:root{
  /* ── DNA 가닥은 오직 이 두 색이다 ── */
  --n15:#7B4FB5;  --n15-bg:#F1EAFA;   /* 15N = 무거운 질소  (--purple) */
  --n14:#0F766E;  --n14-bg:#E2F3F1;   /* 14N = 가벼운 질소  (--teal)   */
  /* ── 기구·판정에만 쓰는 색 ── */
  --gearL:#8A93A6; --gearD:#5A616C;   /* 배지·튜브·저울·원심분리기 = 회색 */
  --ok:#2A7A38;    --no:#C0392B;      /* ✔ 일치 / ✖ 어긋남 (--green / --red) */
  --blue:#1255A0;                     /* UI 크롬(제목·단추)에만 */
  --amber:#E67E22;                    /* 문항 카드 강조에만 */
}
```

**왜 보라·청록인가**
- 파랑·초록·빨강·앰버는 이 프로젝트에서 이미 의미가 굳어 있다 — 파랑=UI 크롬, 초록=정답/완료, 빨강=오답, 앰버=경고·문항. DNA 가닥에 쓰면 「초록 가닥」과 「정답 초록」이 한 화면에서 겹친다.
- 보라·청록은 1-4에서 실험 고유색(e2·e3)이었을 뿐 판정 의미가 없다. 이 파일에서는 자유롭다.
- 색각 이상 대비: 보라와 청록은 2형 색각에서 가까워질 수 있으므로 **색만으로 구분시키지 않는다.** 아래의 형태 중복을 반드시 함께 넣는다.

**형태 중복 (색맹 대비 · 흑백 인쇄 대비)**
- <sup>15</sup>N 칸: 진한 채움 + **칸 안에 작은 점 하나**(`<circle r="1.6" fill="#fff">`) → 「무겁다 = 알맹이가 들었다」
- <sup>14</sup>N 칸: 채움만, 점 없음
- 모든 칸에 흰 0.8px 테두리 → 칸 경계가 늘 보인다

**★절대 하지 말 것 — 가닥 굵기로 무게를 나타내지 말 것.**
「무거우니 굵게」는 그럴듯하지만, 이 활동은 **띠의 굵기 = DNA의 양**을 따로 가르친다. 굵기 뜻이 두 개가 되면 무대 5에서 「가벼운 띠가 더 굵다」가 「가벼운 DNA가 더 무겁다」로 읽힌다. **가닥 칸 크기는 17×9px 로 전 무대 고정**이다.

> ★검증 반영(굵기 표현) — 이 문단의 예시는 원래 「보존적 2세대는 가벼운 띠가 세 배 굵다」였다. 두께 공식 `t = 5 + 11 × ratio`에서 보존적 G2는 7.75 : 13.25(≒1.7배)이므로 「세 배」는 **굵기가 아니라 분자 개수 비(1 : 3)**다. 기본 굵기 5px이 있는 한 굵기가 3배가 되는 일은 구조적으로 없다. **굵기에는 배수를 쓰지 않는다** — 「더 굵다 / 굵기가 같다」까지만 말하고, 배수는 분자 개수에만 쓴다(6-2 국면 5 캡션도 같은 이유로 고쳤다).

**★회색은 DNA에 절대 쓰지 않는다.** 회색은 기구 전용이다.

**범례**(HTML, 무대 바로 위 · 무대 2·3·4·5 카드 왼쪽 칸에 모두 붙인다)

```html
<div class="legend">
  <i class="sw n15"></i><b><sup>15</sup>N 가닥</b> 무거운 질소 &nbsp;·&nbsp;
  <i class="sw n14"></i><b><sup>14</sup>N 가닥</b> 가벼운 질소 &nbsp;·&nbsp;
  <i class="sw mid"></i>중간 무게 = 두 가닥이 한 개씩 섞였다 &nbsp;·&nbsp;
  <i class="sw gear"></i>회색은 기구이다
</div>
```
`.sw.mid{background:linear-gradient(90deg,var(--n15) 0 50%,var(--n14) 50% 100%);}`

## 2. 공용 도형 규격

### 2-1. 분자 `molSvg(x, y, top, bot, opt)`

`top`·`bot`은 길이 8의 문자열/배열, 각 칸이 `'H'`(<sup>15</sup>N) 또는 `'L'`(<sup>14</sup>N).

```
CELL_W = 17, CELL_H = 9, N_CELL = 8
MOL_W  = 136 (= 8 × 17)
가닥 사이 간격 6px → 분자 몸통 높이 24px
칸:      <rect width="17" height="9" fill=(H?--n15:--n14) stroke="#fff" stroke-width=".8">
H 칸 표시: <circle cx=칸중앙 cy=칸중앙 r="1.6" fill="#fff" opacity=".9">
염기쌍:   두 가닥 사이 세로선 8개, x=칸중앙, stroke="#9AA1AC" stroke-width="1"
조각 이음매(분산적 전용): 색이 바뀌는 경계에만 stroke="#3A3F4A" stroke-width="1.4" 세로선
```

분자 아래 라벨 2줄(무대 3에서만):
- 1줄 `y+36`, font-size 12.5, bold, 색은 조성에 따라 — `¹⁵N-¹⁵N` / `¹⁴N-¹⁵N` / `¹⁴N-¹⁴N` / `섞임`
- 2줄 `y+50`, font-size **12.5**, `#555` — `¹⁵N 8칸 / 16칸`  ← ★검증 반영: 11.5였다. 9절의 실제 배율 1.088배에서 11.5는 12.5px이 되어 1-4가 정한 **13px 바닥선**을 뚫는다. 12.5로 올리면 13.6px이다(줄 간격 14px은 그대로 둔다).

### 2-2. 튜브 `tubeSvg(x, y, sc, bands, opt)`

```
튜브 로컬(입구 중앙이 원점, sc=1):
  외곽  M-26,0 L26,0 L26,100 A26,26 0 0 1 -26,100 Z   fill=#F7FAFF stroke=--gearD sw=2.4
  용액  y 8 ~ 118  (rect + 바닥 반원)  fill=#EEF2F7
  눈금  y=34 / 64 / 94  → x 28~40 에 점선 tick, --gearL, stroke-dasharray="3,3"
  이름  가벼운 DNA(34) · 중간 무게의 DNA(64) · 무거운 DNA(94)   ※맨 왼쪽 튜브에만 표기
띠:
  중심 y = 34 + 60 × f15         (f15 = 그 DNA의 ¹⁵N 비율)
  두께 t = 5 + 11 × ratio        (ratio = 전체 분자 중 그 무게가 차지하는 분율)
  폭 48 (x -24 ~ 24), 세로 4칸 분할(칸 폭 12)
    칸 i(0..3) 색 = ( i < round(4 × f15) ) ? --n15 : --n14
  진하기 opacity = 0.5 + 0.5 × ratio
  칸 사이 흰 0.8px 구분선
```

검산: `f15=1 → y=94, 4칸 모두 보라` / `f15=0.5 → y=64, 2:2` / `f15=0 → y=34, 4칸 모두 청록` / `f15=0.25 → y=49, 1:3`
두께: `ratio=1 → 16` / `0.75 → 13` / `0.5 → 11` / `0.25 → 8`

**★`<pattern>`을 쓰지 않는 이유** — 무대마다 `<svg>`를 새로 만들기 때문에 같은 `id`의 `<defs>`가 문서 안에 여러 벌 생긴다. `url(#pMid)`는 **첫 번째**만 잡으므로, 그 첫 SVG가 다시 그려지는 순간 다른 무대의 띠가 통째로 사라진다. 세로 4칸 분할은 `<rect>` 네 개라 이 위험이 없고, 덤으로 「보라 칸이 몇 개인가」를 셀 수 있어 교육적으로 더 낫다.

### 2-4. ★윗첨자 — 무대 안에서는 유니코드를 쓴다

SVG `<text>` 안에 `<sup>`·`<b>`를 넣으면 HTML 파서의 「외래 콘텐츠 이탈」 규칙이 `<text>`와 `<svg>`를 통째로 닫아 **그림이 거기서 끊긴다**(1-4에서 실제로 겪었다).

- **무대(SVG) 문자열에는 `¹⁵N` · `¹⁴N` 유니코드 윗첨자를 그대로 적는다.** (`¹`=U+00B9, `⁴`=U+2074, `⁵`=U+2075) 태그가 없으니 끊길 자리가 없다.
- **HTML 본문·표·문항에는 `<sup>15</sup>N`**을 쓴다(의미가 살아 있고 검색·복사에 유리하다).
- HTML 문구를 무대로 옮길 때는 **반드시 `svgText()`를 거친다** — 1-4의 함수를 그대로 가져와 `<sup>`→`<tspan baseline-shift="super" font-size="0.7em">`로 바꾼다. 이 함수는 안전망이지 1차 수단이 아니다.
- 글꼴이 `⁴`·`⁵`를 못 찍어 두부(□)가 뜨면 그 문자열만 `svgText('<sup>14</sup>N')` 경로로 되돌린다. (본문 글꼴 Noto Sans KR + 시스템 폴백에서는 정상 출력된다.)

### 2-5. ★회전 연출 — 도는 `<g>`와 자리 잡는 `<g>`를 가른다

CSS 애니메이션의 transform이 SVG의 `transform` **속성을 덮어써서** 그림이 0,0으로 튄다(1-4 「원심분리가 안 보인다」의 원인이었다).

```html
<!-- 바깥: 자리만 잡는다. transform 속성 O, class X -->
<g transform="translate(340,150)">
  <circle r="52" fill="none" stroke="#D5D8DE" stroke-width="1.6" stroke-dasharray="5,5"/>
  <!-- 안쪽: 돌기만 한다. class O, transform 속성 X -->
  <g class="spinning">…시험관 2개…</g>
</g>
```
```css
.spinning{animation:spinC .7s linear infinite;transform-box:fill-box;transform-origin:center;}
```
- `transform-box:fill-box`가 없으면 무대 한가운데를 축으로 크게 휘돈다.
- **회전 반지름은 52px**로 작게 유지한다(1-4에서 72→56으로 줄이라는 지시가 있었다).
- 회전 국면에서는 **튜브 속 내용을 그리지 않는다**. 돌 때 띠를 보여 줄 이유가 없고, 작은 도형 안의 띠는 어차피 안 읽힌다.

### 2-6. 저울은 CSS 애니메이션을 쓰지 않는다

빔이 도는 `<g>`이므로 2-5의 함정에 그대로 걸린다. **국면이 바뀔 때 각도를 속성으로 다시 그린다**(전환 애니메이션 없음). 자동으로 `prefers-reduced-motion`도 지켜진다.

접시는 **기울어지면 안 된다**. 빔 끝점을 JS로 계산해 회전 `<g>` **바깥**에 절대좌표로 놓는다.

```
θ = 0° / 6° / 12°   (¹⁵N 가닥 0개 / 1개 / 2개)
빔 반팔 길이 L = 110
왼쪽 끝  (367 - L·cosθ, 150 + L·sinθ)
오른쪽 끝(367 + L·cosθ, 150 - L·sinθ)
→ 12°에서 좌우 높이차 46px. 확실히 보인다.
```

### 2-7. `prefers-reduced-motion`

```css
@media (prefers-reduced-motion: reduce){
  .spinning,.hot,.shaking{animation:none !important;}
  .ani-fade,.ani-move,.ani-grow{transition:none !important;}
}
```
그리고 JS에서:
```js
var REDUCED = (typeof matchMedia === 'function') &&
              matchMedia('(prefers-reduced-motion: reduce)').matches;

## 3. 엔진 계승 — 1-4에서 반드시 고쳐야 하는 것

1-4의 `ANI_LAST`는 **상수 4**다. 그대로 복사하면 국면이 6개인 무대(배양·복제·대조)가 **국면 4에서 멈추고 마지막 두 장면을 영영 못 본다.** 이것이 이번 이식에서 가장 큰 함정이다.

```js
/* ① 무대·조건마다 국면 수가 다르다 — 상수를 함수로 바꾼다 */
function aniLast(st, id){ return aniSteps(st, id).length - 1; }
/* ph >= ANI_LAST  →  ph >= aniLast(st, id)   (aniOf/aniPlaying/aniStep/aniSkip/aniGo/aniHold 전부)
   aniOf(st,id) 의 기본 반환값도 ANI_LAST → aniLast(st,id) */

/* ② 국면마다 머무는 시간을 다르게 준다 — 숫자 또는 배열을 받는다 */
var ANI_MS = {
  cul : 1100,
  bal : 1000,
  rep : [1200, 1300, 2200, 1800, 2200, 1800],  /* 진입하는 국면 번호로 색인 */
  spin: [1200, 1300, 2000, 1700, 1500],
  cmp : 1900
};
function aniMs(st, phEntering){
  var v = ANI_MS[st];
  if (v == null) return 1200;
  return (typeof v === 'number') ? v : (v[phEntering] != null ? v[phEntering] : 1200);
}

/* ③ 국면 이름 */
var ANI_STEPS = { cul:[...], bal:[...], rep:[...], spin:[...], cmp:[...] };
var ANI_STEPS_BY_ID = { rep:{ cons:[...], semi:[...], disp:[...] } };   /* 1-4의 av:none 선례 그대로 */

/* ④ renderStage 등록 */
function renderStage(st){
  if (st==='cul') renderCul(); else if (st==='bal') renderBal();
  else if (st==='rep') renderRep(); else if (st==='spin') renderSpin();
  else if (st==='cmp') renderCmp();
}
```

`aniRelease` / `aniHold` / `aniReplay` / `aniGo` / `aniSkip` / `aniBarHtml` / `svgOpen` / `svgText`는 1-4를 **그대로** 가져온다(`aniLast` 치환만). 제어 막대는 `[⏮ 처음부터][◀ 이전][▶ 다음][⏩ 끝까지] + 국면 이름 n / N` 형태를 유지한다.

**결정성 규칙**: 흩어진 조각·점의 좌표에 `Math.random()`을 쓰지 않는다. 고정 좌표표를 쓴다 — 다시 보기 때 그림이 달라지면 「같은 실험인가」가 흔들리고, `_test_메셀슨.js` 회귀 검사도 못 쓴다.

| **2** | cons `원본을 그대로 두고 베낀다` / semi `두 가닥이 갈라진다` / disp `분자가 조각으로 잘린다` | 아래 6-3 참조 | cons `원래 두 가닥은 붙어 있다. \| 옆에 새 분자를 따로 만든다.` / semi `두 가닥이 지퍼처럼 갈라진다. \| 갈라진 가닥이 각각 주형이 된다.` / disp `분자가 여덟 조각씩 잘린다. \| 새 조각과 섞여 다시 이어진다.` |
| **3** | `1세대(G1) — 분자 2개` (공통) | G1 행에 분자 2개 + 조성 라벨 2줄. P 행 분자는 흐리게(opacity .3) 남겨 출처를 보인다 | cons `무거운 DNA 하나와 가벼운 DNA \| 하나가 생긴다. 띠가 둘이다.` / semi `두 분자 모두 ¹⁴N-¹⁵N이다. \| 중간 무게의 띠 하나가 생긴다.` / disp `두 분자 모두 ¹⁵N이 절반이다. \| 중간 무게의 띠 하나가 생긴다.` |
| **4** | cons `다시 원본만 남기고 베낀다` / semi `네 가닥이 각각 갈라진다` / disp `조각이 다시 잘리고 섞인다` | 6-3의 동작을 G2 행 자리에서 반복 | cons `원본은 이번에도 그대로 남는다.` / semi `네 가닥이 각각 주형이 된다.` / disp `조각이 다시 잘려 ¹⁵N이 \| 절반으로 줄어든다.` |
| **5** | `2세대(G2) — 분자 4개` (공통) | G2 행에 분자 4개 + 조성 라벨. 오른쪽 위 카운터 갱신 | cons `무거운 하나, 가벼운 셋이다. \| 가벼운 DNA가 세 배 많다.` / semi `중간 무게 둘, 가벼운 둘이다. \| 두 띠의 굵기가 같다.` / disp `네 분자 모두 조성이 같다. \| 띠는 여전히 하나뿐이다.` |

> ★검증 반영(국면 5 cons 캡션) — 원래 2줄이 「가벼운 띠가 세 배 굵다.」였다. 두께 공식으로는 7.75 : 13.25(≒1.7배)라 화면과 어긋나고, **무대 3에는 띠가 아예 그려지지 않아** 학생이 확인할 수단도 없다. 「세 배」는 분자 개수 비이므로 **분자 수 진술로 바꾼다** — `가벼운 DNA가 세 배 많다.`(16자, 20자 규칙 통과). 굵기 비교는 띠가 실제로 그려지는 무대 4·5의 몫으로 남긴다. semi의 「두 띠의 굵기가 같다」는 11 : 11로 실제와 맞으므로 그대로 둔다.
>
> 위 캡션은 **모든 줄이 20자 이하**가 되도록 다듬은 것이다. 「¹⁵N-¹⁵N 하나, ¹⁴N-¹⁴N 셋이다.」처럼 동위원소 표기를 그대로 늘어놓으면 24~25자가 되어 viewBox 밖으로 잘린다. 조성의 정확한 표기는 **분자 아래 라벨**과 **오른쪽 칸 표**가 맡고, 무대 캡션은 「무거운/중간 무게의/가벼운」이라는 띠 이름으로 짧게 말한다.

### 6-3. ★세 모델의 「동작」을 어떻게 다르게 그리는가 (국면 2·4)

이 세 그림이 다르지 않으면 활동 전체가 실패한다.

**보존적 `cons`** — 원본은 **한 번도 벌어지지 않는다**.
```
· 위 행의 분자를 통째로 아래로 내려 왼쪽 자리(x=192)에 그대로 놓는다. 두 가닥이 붙어 있는 채다.
· 그 분자에서 오른쪽 자리(x=352)로 굵은 점선 화살표 + 라벨 「보고 베낀다」(font 12.5, --gearD)
· 오른쪽 자리에는 청록 칸이 왼쪽부터 차례로 8칸 채워지는 중(4칸까지 그려 「만드는 중」을 표현)
· ¹⁴N 풀의 점 몇 개가 오른쪽 분자 쪽으로 이동
```
**반보존적 `semi`** — 지퍼가 열린다.
```
· 위 행 분자의 두 가닥이 위·아래로 벌어진다(간격 6 → 34px). 오른쪽 끝은 아직 붙어 있어 V자로 갈라진 모양
· 벌어진 틈에 청록 칸이 왼쪽부터 붙는다(각 가닥에 4칸까지)
· 두 가닥 각각에 「주형」 라벨(font 12.5 — ★검증 반영: 11.5는 1.088배에서 12.5px으로 13px 바닥선을 뚫는다)
· 갈라진 지점에 작은 화살표 ▶ 「풀리는 방향」
```
**분산적 `disp`** — 잘리고 섞인다.
```
· 위 행 분자가 16조각으로 흩어진다. 조각 = rect 17×9, 고정 산포 좌표 16개
     SCATTER16 = [[-58,-16],[-34,-4],[-12,-18],[8,-6],[30,-20],[52,-8],[-46,10],[-24,20],
                  [-2,8],[18,22],[40,10],[60,20],[-66,2],[-16,-28],[26,-30],[68,0]]
     (중심 (340,155) 기준 오프셋. 조각 색은 전부 --n15)
· 그 사이에 ¹⁴N 새 조각(청록) 16개가 다른 고정 좌표로 섞여 든다
· 국면 3에서 두 자리로 모여 HLHLHLHL / LHLHLHLH 배열로 재조립된다
· 조각 경계마다 짙은 이음매 선(1.4px #3A3F4A) → 「이어 붙인 자국」이 보인다
```

### 6-4. 오른쪽 칸에 둘 표 (무대와 짝을 이룬다)

> ★검증 반영(섞임 칸 신설) — 원래 표는 열이 `¹⁵N-¹⁵N / ¹⁴N-¹⁵N / ¹⁴N-¹⁴N` 셋뿐이라 **분산적 분자를 적을 칸이 없었다.** 6-1이 정한 대로 disp G1은 `top HLHLHLHL / bot LHLHLHLH`, 즉 두 가닥 모두 조각 모자이크여서 어느 가닥도 순수한 ¹⁴N·¹⁵N 가닥이 아니다. 그런데도 disp G1의 2개를 `¹⁴N-¹⁵N` 칸에 적으면 **표가 「분산적 1세대 = 한 가닥 통째로 ¹⁵N + 한 가닥 통째로 ¹⁴N」이라는 오개념을 직접 가르치고**, 반보존적과 분산적을 가르는 유일한 분자 수준 차이(6-3 국면 2·4 연출 전체의 존재 이유)를 표가 지워 버린다. 2-1의 분자 라벨 규격에는 이미 네 번째 라벨 `섞임`이 있는데 표에만 그 칸이 없었다 → **「섞임(조각)」 열을 더해 2-1의 라벨 네 종과 일치시킨다.** 분산적 G1(8/16)과 G2(4/16)를 가르는 것은 맨 오른쪽 「한 분자의 ¹⁵N 칸 수」 열이 맡는다.

| 세대 | 분자 수 | ¹⁵N-¹⁵N | ¹⁴N-¹⁵N | ¹⁴N-¹⁴N | 섞임(조각) | 한 분자의 ¹⁵N 칸 수 |
|---|---|---|---|---|---|---|
| P | 1 | 1 | 0 | 0 | 0 | 16 / 16 |
| G1 | 2 | 모델별 | 모델별 | 모델별 | 모델별 | 모델별 |
| G2 | 4 | 모델별 | 모델별 | 모델별 | 모델별 | 모델별 |

**모델별 채움값**(6-1의 칸 배열에서 그대로 나온다 — 구현자는 이 표를 눈금으로 쓴다)

| 모델 | 세대 | ¹⁵N-¹⁵N | ¹⁴N-¹⁵N | ¹⁴N-¹⁴N | 섞임(조각) | 한 분자의 ¹⁵N 칸 수 |
|---|---|---|---|---|---|---|
| 보존적 | G1 | 1 | 0 | 1 | 0 | 16/16 · 0/16 |
| 보존적 | G2 | 1 | 0 | 3 | 0 | 16/16 · 0/16 |
| 반보존적 | G1 | 0 | 2 | 0 | 0 | 8/16 |
| 반보존적 | G2 | 0 | 2 | 2 | 0 | 8/16 · 0/16 |
| 분산적 | G1 | 0 | 0 | 0 | 2 | 8/16 |
| 분산적 | G2 | 0 | 0 | 0 | 4 | 4/16 |

★**반보존적 G1과 분산적 G1은 「한 분자의 ¹⁵N 칸 수」가 똑같이 `8/16`이고, 조성 열에서만 갈린다**(`¹⁴N-¹⁵N` ↔ `섞임`). 6-1이 말한 결정적 장면이 표에서도 그대로 보인다. 무대 5 국면 3의 「한 번으로는 못 가른다」가 이 두 행에서 시작한다.

세 모델을 다 실행하기 전에는 그 모델 행만 채워지고 나머지는 `아직 실행하지 않았다`(1-4의 `td.wait` 스타일)로 둔다. 셋을 다 실행해야 문항이 열린다(1-4의 `hcQwrap` 잠금 패턴 그대로).

## 7. 무대 4 — 원심분리 무대 `spin`

**viewBox `0 0 680 330` · 시간 `[1200,1300,2000,1700,1500]` · 국면 5개(0~4) · 조건 id = `P` / `G1` / `G2`**

실제 실험의 세 튜브를 학생이 하나씩 돌린다.

```js
var SPIN_BANDS = {
  P : [{f15:1,   ratio:1  }],                              /* 무거운 띠 하나, 두께 16 */
  G1: [{f15:0.5, ratio:1  }],                              /* 중간 띠 하나,   두께 16 */
  G2: [{f15:0.5, ratio:0.5}, {f15:0, ratio:0.5}]           /* 중간·가벼운,   각 두께 11 */
};
```

큰 튜브 `sc = 1.6` (폭 83, 직선부 160, 총 높이 202), 위치 x=250, y=48. 오른쪽 x 420~660은 주석 구역.

| 국면 | 국면 이름 | 무대에 보이는 것 | 캡션 |
|---|---|---|---|
| **0** | `튜브에 DNA를 넣는다` | 큰 튜브. 용액 안에 DNA 점 24개가 **고르게** 흩어짐(고정 좌표, r=4). 점 색은 그 세대의 조성대로 — P는 24개 보라 / G1은 반반 섞인 점(왼쪽 반 보라·오른쪽 반 청록인 작은 원) / G2는 12개 섞임점 + 12개 청록 | `DNA가 튜브 전체에 \| 고르게 흩어져 있다.` |
| **1** | `원심분리기에 건다` | 튜브가 작아져(sc .6) 회전자에 걸린다. 원심분리기 몸통 `rect x=250 y=76 w=180 h=150 rx=16` + 회전자 중심 (340,150), 정지 상태 | `튜브 두 개를 마주 보게 건다.` |
| **2** | `돌린다` | 2-5 패턴 그대로. 바깥 `<g transform="translate(340,150)">` + 안쪽 `<g class="spinning">`. 시험관 `rect x=-13 y=-52 w=26 h=38 rx=4`, r=52 점선 궤도. **튜브 속 내용 없음** | `빠르게 돌리면 \| 큰 힘이 걸린다.` |
| **3** | `밀도에 따라 모인다` | 회전 멈춤. 큰 튜브 복귀. 점 24개가 각자의 y(=34+60·f15, ×1.6)로 **아직 조금 퍼진 채** 모인다(±9px 흔들림, 고정 좌표) | `밀도가 같은 DNA끼리 \| 같은 높이에 모인다.` |
| **4** | `띠를 읽는다` | 점이 사라지고 `tubeSvg(bands=SPIN_BANDS[id])`. 오른쪽 주석 2개: ① 튜브 왼쪽에 세로 양방향 화살표 + `높이 = 밀도` ② 띠 오른쪽에 가로 양방향 화살표(띠 두께만큼) + `굵기 = DNA의 양` | `띠의 높이는 밀도이다. \| 띠의 굵기는 DNA의 양이다.` |

★국면 3과 4를 반드시 나눈다. 1-4 검토에서 「마지막 [▶ 다음]이 새로 보여 주는 것이 없다」는 지적을 받았다 — 여기서는 **퍼진 점 → 선명한 띠 + 주석**이 새로 나타난다.

## 8. 무대 5 — 대조 무대 `cmp` (배제 논리의 결승점)

**viewBox `0 0 680 390` · 시간 1900ms · 국면 6개(0~5) · 조건 id 없음(`'all'` 하나)**

가장 느리게 간다. 읽을 것이 가장 많다.

### 배치 (4열 × 2행)

```
행 라벨 열  x = 52   (1세대(G1) / 2세대(G2))
열 중심     실제 148 · 보존적 282 · 반보존적 416 · 분산적 550   (pitch 134)
열 이름 행  y = 20   font 13.5 bold
G1 행       튜브 top y = 46    (sc 0.85 → 폭 44, 높이 107)
G2 행       튜브 top y = 196
캡션        y = 350 / 370
```
**열 순서는 교과서 순서(보존적 → 반보존적 → 분산적)를 지킨다.** 판정 순서는 배지가 말한다 — 열을 옮겨 다니게 하지 않는다.
**「실제」 열은 테두리를 두껍게**(`rect` 둘레 2.5px `#1A1A1A`, 배경 `#FBFCFE`) 하고 열 이름 위에 검은 배지 「실제」를 단다.

### 띠 데이터

```js
var CMP = {
  real:{ G1:[{f15:.5,ratio:1}],              G2:[{f15:.5,ratio:.5},{f15:0,ratio:.5}] },
  cons:{ G1:[{f15:1,ratio:.5},{f15:0,ratio:.5}], G2:[{f15:1,ratio:.25},{f15:0,ratio:.75}] },
  semi:{ G1:[{f15:.5,ratio:1}],              G2:[{f15:.5,ratio:.5},{f15:0,ratio:.5}] },
  disp:{ G1:[{f15:.5,ratio:1}],              G2:[{f15:.25,ratio:1}] }
};
```
검산 — 보존적 G1은 무거운·가벼운이 **각각 두께 11로 같다**(교사용 「같은 두께로 나타나야 하지만」과 정확히 일치). 보존적 G2는 두께 **8 : 13** → **가벼운 띠가 눈에 띄게 굵다**. 반보존적 G2는 11 : 11 → **「비슷하게」**. 교과서 문장이 그림에서 그대로 재현된다.

> ★검증 반영(검산 수치) — 원래 「8 : 20」이라 적혀 있었다. `t = 5 + 11 × ratio`에서 ratio 0.75 → **13.25**(2-2의 검산표도 「0.75 → 13」이다)이고 ratio = 1일 때의 **최댓값이 16**이므로 20은 나올 수 없는 값이다. 검산 줄은 구현자가 그대로 눈금 삼는 자리라, 이 숫자에 맞추려고 공식을 건드리면 다른 무대의 띠까지 어긋난다. 뒤에 붙은 판단(「눈에 띄게 굵다」)은 8 : 13(≒1.7배)에서도 그대로 성립한다.

### 국면표

| 국면 | 국면 이름 | 무대에 보이는 것 | 캡션 |
|---|---|---|---|
| **0** | `실제 실험 결과` | **실제 열만** 그린다. 나머지 3열은 연회색 점선 자리표시 + 「?」. 눈금 이름 3개는 실제 열에만 | `1세대는 띠가 하나, \| 2세대는 띠가 둘이다.` |
| **1** | `세 모델의 예상을 나란히 놓는다` | 보존적·반보존적·분산적 3열이 한꺼번에 나타난다(`.ani-fade`). 배지는 아직 없음 | `예상과 실제가 같은지 \| 맞춰 보시오.` |
| **2** | `1세대 — 보존적을 지운다` | 보존적 **G1 튜브**를 빨간 점선 테두리(3px dash 5,4 `--no`)로 감싸고 오른쪽 위에 ✖ 배지(원 r=11 `--no`, 흰 ✖). 그 아래 빨간 라벨 「1세대에서 어긋난다」. 실제 G1 ↔ 보존적 G1 사이에 빨간 점선 잇는 선 | `보존적은 1세대에서 무거운 띠와 \| 가벼운 띠가 둘 다 나와야 한다.` |

### ★분산적 2세대 띠 높이 — 교과서와의 어긋남을 어떻게 다룰 것인가 (결정 요청)

교사용 46쪽은 「분산적이면 2세대에 **중간 무게의 DNA 띠만** 나타나야 한다」고 적었다. 그러나 이 활동은 「띠 높이 = <sup>15</sup>N 비율」을 규칙으로 가르치고, 분산적 2세대는 <sup>15</sup>N이 4분의 1이다. 규칙대로면 띠는 **y=49**(중간 64보다 15px 위)에 앉는다. 무대 3에서 학생이 직접 「보라 4칸 / 16칸」을 세게 해 놓고 띠만 중간에 그리면, 눈 밝은 학생이 바로 걸고넘어진다.

- **권고**: 규칙대로 **y=49**에 그린다(`f15:0.25`). 배제 근거는 높이가 아니라 **띠의 개수**로 말한다 — 「분산적은 어느 세대에서든 모든 분자의 조성이 같으므로 **띠가 언제나 하나**이다. 실제 2세대는 띠가 **둘**이다.」 이 논법은 교과서 결론과 완전히 같고 더 튼튼하다.
- 오른쪽 칸에 💡 보충 상자를 함께 둔다(시험지 문체):
  > 💡 교과서 그림은 분산적 복제의 2세대 띠를 중간 무게 자리에 그려 두었다. 엄밀히 따지면 ¹⁵N의 비율이 4분의 1로 줄어 띠는 중간보다 조금 위에 생긴다. 어느 쪽이든 **띠가 하나**라는 점은 같고, 분산적 복제를 지우는 근거는 바로 그것이다.
- 교사가 교과서 그림과 똑같이 두기를 원하면 상수 하나로 뒤집는다:
  ```js
  var DISP_G2_AT_MIDDLE = false;   // true 로 두면 분산적 G2 띠를 f15 0.5(중간 자리)에 고정한다
  ```

## 11. 회귀 검사에 넣을 항목 (`_test_메셀슨.js`)

1. **국면 수** — 다섯 무대 × 모든 조건 id에 대해 `aniSteps(st,id).length`가 표와 일치하는가. `aniLast`가 상수 4로 남아 있지 않은가.
2. **캡션 길이** — 모든 캡션의 각 줄이 **20자 이하**인가(공백 포함). 넘으면 viewBox 밖으로 잘린다.
3. **SVG 안의 태그** — 모든 무대 문자열에 `<sup>`·`<b>`·`<strong>`·`<i>`가 남아 있지 않은가(있으면 그림이 끊긴다). `¹⁵N`/`¹⁴N` 유니코드만 허용.
4. **회전 `<g>`** — `class="spinning"`을 가진 요소에 `transform` **속성**이 함께 있지 않은가.
5. **색 규약** — 무대 문자열에 `--n15`·`--n14`·기구 회색·판정 색 밖의 색상 리터럴이 섞이지 않았는가. 특히 DNA 도형에 `#8A93A6`·`#6B7280`이 쓰이지 않았는가.
6. **띠 계산** — `bandY(f15) === 34 + 60*f15`, `bandT(r) === 5 + 11*r`, 4칸 분할 색 = `i < round(4*f15)`.
7. **모델별 조성 합** — cons/semi/disp 각 세대의 `¹⁵N 칸 수 합`이 언제나 **16**(P 유래분 보존)인가. G1 합 16, G2 합 16.
8. **결정성** — 같은 무대를 두 번 그린 문자열이 완전히 같은가(난수 금지 확인).
9. **말투** — 10절의 금지어·어미 검사.
10. **잠금** — 무대 3의 세 모델을 다 실행하기 전에는 무대 5 카드와 정리 문항이 잠겨 있는가. 새 탭에서도 잠겨 있는가(1-4에서 실제로 새 탭이 열려 있었다).

전체를 한 번씩 끝까지 보면 약 **6.6 + 5.0×4 + 10.5×3 + 7.7×3 + 11.4 ≒ 93초**다. `bal`은 조건 id가 `LL`·`LH`·`HL`·`HH` 네 개이므로 네 번 돈다. 다만 **`LH`와 `HL`은 결과가 같으므로**(5절 표) 실제 수업에서는 세 번만 돌려도 되고, 그러면 약 **88초**다. 각 무대는 언제든 [⏮ 처음부터]로 다시 볼 수 있고, [◀ 이전]/[▶ 다음]으로 한 국면씩 세울 수 있다.

> ★검증 반영(합계 시간) — 원래 「6.6 + 5.0 + 10.5×3 + 7.7×3 + 11.4 ≒ 78초」였다. 조건 id 수를 무대마다 다르게 셌다 — `rep`(3모델)·`spin`(3튜브)은 ×3으로 곱하면서 조건 id가 **네 개**인 `bal`만 ×1로 넣었다. 「전체를 한 번씩 끝까지 보면」이라는 전제대로면 `bal`은 5.0×4 = 20.0초여야 한다.
