# 🔧 복습 퀴즈를 늘리는 표준 절차

> 대상 = https://lifescience-quiz.web.app/**gen** (생물의 유전). 배포·운영 이력은 [[생물의유전_복습퀴즈]], 문항 원문은 `생물의 유전/복습퀴즈/`.
> 이 절은 **2026-09-09에 한 번 크게 데인 뒤** 만든 것이다(아래 「왜 이렇게 하는가」).

## 지켜야 할 것 세 가지

1. **한 소단원 = 한 퀴즈** (2026-09-09 교사 지시). 「기초/심화」로 카드를 쪼개지 않는다.
   한 퀴즈 안에서 앞쪽에 개념·용어, 뒤쪽에 자료·그림·계산을 놓는다.
2. **문항은 뒤에만 이어 붙인다. 퀴즈 id 는 바꾸지 않는다.**
   학생 진도가 `progress/{uid}/{quizId} = {seen:{문항번호:true}}` 로 **문항 번호**에 매여 있다.
   앞에 끼우거나 순서를 바꾸면 이미 푼 학생의 진도가 통째로 어긋난다. id 를 바꾸면 진도·응시 기록이 통째로 떨어져 나간다.
3. **올리는 길은 하나** — `생물의 유전/활동/_퀴즈올리기.js`. 일회용 스크립트를 새로 만들지 않는다.

## 절차

| 단계 | 무엇을 | 어떻게 |
|:-:|---|---|
| 1 | 교과서 해당 쪽 **전문 추출** | `PYTHONIOENCODING=utf-8 python -c "import fitz; ..."` · `생물의 유전/교과서_단원별/` · 교사용은 `교과서_단원별_교사용/`(탐구 답·지도 유의점이 여기 있다) |
| 2 | **문항 md 작성** → 교사 검토 | `생물의 유전/복습퀴즈/유전<소단원>_복습퀴즈_문항모음.md`. 양식·규칙은 그 폴더 `README.md` |
| 3 | **조립기에 옮겨 적기** | `_build_퀴즈_<범위>.js` — 문항 객체 배열을 내보낸다(`module.exports = { questions }` 또는 `{ quiz }`) |
| 4 | **확인** (쓰기 없음) | `node "생물의 유전/활동/_퀴즈올리기.js" --append <퀴즈id> <조립기>` |
| 5 | **올리기** | 같은 명령에 `--write`. 백업 → 쓰기 → 재검증까지 자동 |

- 새 소단원이면 4·5 단계에서 `--append` 대신 `--new <조립기>` 를 쓴다(차례 order 는 10 간격: 50·60·70·80·90).
- 인수 없이 `node _퀴즈올리기.js` 만 치면 **지금 라이브 상태**만 찍는다. 이게 라이브 확인의 정본이다.
- 학교망이 TLS 검사 프록시라 실패하면 앞에 `NODE_TLS_REJECT_UNAUTHORIZED=0` 을 붙인다.

## 도구가 대신 막아 주는 것 (`_퀴즈검사.js`)

문항마다: 선택지 4개 · 정답 번호 범위 · 발문/해설 존재 · **해설 존댓말** · chapter · tagClass ·
선택지 중복·빈칸 · 외부 URL · 꺾쇠 `<보기>`(→【보기】) · **위첨자 문자 금지(`<sup>` 태그를 쓸 것)** ·
**해설이 말하는 정답 번호와 answer 대조**.
퀴즈마다: `subject:'gen'` · **이름에 「기초/심화」 없음** · 차례 겹침 · 발문 중복 · 정답 번호 쏠림 ·
**이어 붙인 뒤 앞 문항이 한 글자도 안 바뀌었는가**.

> 새로 데면 규칙을 **`_퀴즈검사.js` 에 한 줄 더한다.** 노트에만 적으면 다음에 또 밟는다.

## 왜 이렇게 하는가 — 2026-09-09에 있었던 일

- 그날까지는 **바꿀 때마다 일회용 스크립트**를 새로 만들었다. 그러다 단원 통합 도중 **DB 규칙에 막혀(401) 중간에 끊겼고**,
  그 사이 학생 화면에 **카드가 7장(중복 2장)** 그대로 보였다. 교사가 먼저 발견해 물었다.
- 그래서 ① 도구를 하나로 고정하고 ② **끊겨도 이어서 실행되게** 만들고 ③ 검사를 공용 모듈로 뺐다.

### 알아 둘 DB 규칙 (실측)
- `quizzes/` · `quizMeta/` — 자유롭게 쓰고 지운다.
- `results/{quizId}/{key}` — **새 키 쓰기·노드 삭제는 되지만, 이미 있는 기록 수정(PATCH)은 401.**
- `progress/{uid}/{quizId}` — 자유롭게 쓰고 지운다.
- 익명 인증(identitytoolkit signUp)만 하면 위 권한이 나온다. `apiKey`·`databaseURL` 은 라이브 index.html 에 있다
  (`curl -sk https://lifescience-quiz.web.app/ -o live_index.html`).

### 퀴즈 id 를 꼭 바꿔야 할 때만 (드물다)
`_migrate_퀴즈_단원통합.js` 가 본보기다 — **quizzes·quizMeta·progress·results 를 통째로 백업**하고,
진도는 문항 번호를 밀어서, 응시 기록은 같은 키로 복사한 뒤 옛 노드를 지운다. **중단돼도 다시 실행하면 이어서 한다.**
🟡 그때 옮긴 응시 기록 1건은 **답안 번호가 10칸 밀려 보인다**(DB 규칙이 수정을 막아 표시를 못 달았다).

## 커밋할 때
- ★**`git add -A` 금지.** 다른 세션이 동시에 편집한다 — 2026-09-09에 실제로 **작업 중이던 퀴즈 파일이 남의 커밋에 섞여** 들어갔다.
  경로를 찍어서 담을 것: `git add "생물의 유전/복습퀴즈" "생물의 유전/활동/_퀴즈*.js" 작업노트/...`
- 문항 md·노트에 **학생 실명·학번을 쓰지 않는다**(이 저장소는 PUBLIC). 응시 기록을 확인할 때 이름이 보여도 노트에 옮기지 않는다.
