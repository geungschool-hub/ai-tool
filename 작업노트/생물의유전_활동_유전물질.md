## 1. 이 활동이 노리는 것 한 가지

세 실험을 **각각** 아는 것은 ②③④에서 끝난다. 이 활동이 실제로 가르치는 것은 하나다.

> **n번째 실험이 남긴 물음이 (n+1)번째 실험의 물음이 된다.**

그래서 두 곳에 같은 장치를 박아 두었다.

1. **남긴 질문 배너** — ②③④를 마칠 때마다 「이 실험이 답하지 못한 것」이 열리고, 그것이 다음 카드의 제목이 된다.
2. **⑤ 사슬판의 쌍둥이 카드** — n행 「남은 질문」과 (n+1)행 「답하려 한 질문」에 **글자 하나 다르지 않은 같은 문장**이 들어간다.
   덱에 같은 문장이 두 장 있다는 사실 자체가 사슬의 증거다. **설명으로 알려 주지 않는다.**

★코드에서 이 동일성을 검사가 못 박고 있다 — `HANDOFF[n].q === CH_CARDS(L1/L2).text`.
문장을 고칠 때 **한쪽만 고치면 검사가 문다.**

## 3. 설계에서 못 박은 것 (고치기 전에 읽을 것)

### ★연출 제어 — 다시 보기 · 단계별 진행 (2026-08-25 교사 지시)

> 「**애니메이션 다시 보기** 기능이 필요하다.」
> 「허시와 체이스 실험에서 애니메이션이 **좀 빠르다. 단계별로 진행**할 수 있게 해줘야 할듯?」

무대 **바로 아래**(2단 배치의 왼쪽 칸)에 제어 막대를 두었다. `aniBarHtml(st, id, 색)`.

| 단추 | 하는 일 |
|---|---|
| ⏮ 처음부터 | `aniReplay(st,id)` — 0국면부터 자동으로 다시 재생 |
| ◀ 이전 · ▶ 다음 | `aniGo(st,id,±1)` — 손으로 한 단계. **누르는 순간 자동 진행이 끊긴다** |
| ⏩ 끝까지 | `aniSkip(st,id)` |
| 오른쪽 글 | `ANI_STEPS[st][ph]` + 「4 / 5」 — 지금 어느 단계인지 |

- **속도는 무대마다 다르다** — `ANI_MS = {gr:900, av:900, hc:1600}`. 허시·체이스는 감염·믹서·원심분리·측정으로
  볼 것이 많아 느리게 잡았다(교사가 「빠르다」고 한 그 무대다). 검사가 `hc > gr` 을 못 박는다.
- **③④의 다 한 칩을 잠그지 않는다.** 누르면 그 조건의 연출을 다시 본다.
  잠가 두면 **마지막에 실행한 것 말고는 무대에 다시 불러올 방법이 없었다.**
- **②는 주사기에 그 조합을 다시 넣으면** 무대가 그 조건으로 돌아오고 막대가 뜬다.
  아직 실행하지 않은 조건에는 막대가 없다(볼 연출이 없다).

#### 못 박은 것
- **`ani.gen`(세대 번호)** — 손으로 단계를 넘기면 올라간다. 예약돼 있던 `setTimeout` 은 자기 gen 이 낡은 것을
  보고 **조용히 끊긴다.** 이게 없으면 손으로 3국면에 세워 둔 뒤 잠시 있으면 저절로 4로 넘어가 버린다.
  브라우저에서 2.2초 기다려 **ph 가 3에 머무는 것을 확인**했다.
- **`ani.reveal`** — 「이번 재생이 처음 밝히는 재생인가」. `aniPlaying()` 이 이 값을 본다.
  다시 보기(`reveal:false`)일 때는 **결과표가 「관찰 중이다…」로 되돌아가지 않는다** — 이미 아는 결과를 감출 이유가 없다.
  처음 실행(`aniStart(st,id,true)`)일 때만 표가 단계에 맞춰 밝혀진다.
  ★**끝까지 간 뒤에 손으로 되돌아가는 것도 다시 보기다** — `aniHold` 가 `ph >= ANI_LAST` 일 때 reveal 을 내린다.
  이게 없어서 실제로 깨졌다: 처음 실행이 끝난 뒤 ◀ 이전을 누르니 (라) 행이 「관찰 중이다…」로 되돌아갔다
  (2026-08-25 브라우저에서 눈으로 발견). 아직 처음 재생 중이면 reveal 을 그대로 둔다.
- **다시 보기는 `state.grRun/avRun/hcRun` 도 저장분도 건드리지 않는다.** 결과는 실행한 순간 이미 확정돼 있다.
  검사가 이 둘을 함께 문다(변이로 확인).

### ★함정 — CSS 애니메이션은 SVG의 `transform` 속성을 덮어쓴다

**「원심분리 애니메이션이 안 보인다」의 원인이 이것이었다**(2026-08-25 교사 발견).

```
<g class="spinning" transform="translate(340,120)">   ← .spinning 이 만든 CSS transform 이
                                                          이 속성을 통째로 덮어쓴다
```
회전이 시작되는 순간 시험관이 **0,0(무대 왼쪽 위 모서리)으로 튀어** 대부분 화면 밖에서 돌았다.

→ **자리 잡는 `<g>` 는 밖, 도는 `<g>` 는 안**으로 갈랐다. 도는 쪽에는 `transform` 속성을 주지 않는다.
→ `.spinning{transform-box:fill-box; transform-origin:center;}` — **`fill-box` 가 없으면**
   기본값(`view-box`)이라 **무대 한가운데를 축으로 크게 휘돈다.**
→ 도는 반지름을 **72 → 56** 으로 줄이고(교사: 「돌아가는 원의 지름을 줄여봐」) 시험관 **두 개를 마주 보게**
   달아 회전자처럼 보이게 했다. 궤도를 점선 원으로 그려 두었다.
→ 단계를 손으로 넘길 수 있으므로 `.spinning`·`.shaking` 을 **횟수 대신 `infinite`** 로 바꿨다 — 머무는 동안 계속 돈다.
   `prefers-reduced-motion` 에서는 그대로 멈춘다.

검사가 넷을 문다: 도는 `<g>`에 transform 속성 없음 · 자리 잡는 `<g>` 있음 · `fill-box` 있음 · `infinite` 임.
**새 활동에서 SVG를 CSS로 돌릴 때 이 절을 복제해 쓸 것.**

### ★⑤ 카드 덱 — 섞어서 내고, 판을 왼쪽에 고정한다 (2026-08-25 교사 지시)

> 「카드가 안 섞여 있으니 찾는 맛도 안 나고, 계속 스크롤해야 되니까 좀 힘드네?

  고를 것이 없으니 찾는 맛이 날 수가 없었다.
- **한 번 섞은 차례는 `state.deckOrder` 에 남긴다** — 카드를 놓을 때마다 다시 섞이면 눈이 못 따라간다.
  ★`deckOrder` 는 **배열**이라 `init()` 의 복원 병합이 걸러내고 있었다(거기는 객체만 받는다).
  새로고침하면 덱이 다시 섞이던 것 — 따로 되살리도록 고쳤다.
- 난도를 바꾸거나 「이 판 다시 놓기」를 하면 다시 섞는다.

- **덱을 8장으로 줄였다** (같은 날 이어진 지시: 「카드가 8개만 있으면 될 것 같애 너무 많으니까 너무 귀찮네」).

## 4. ★함정 — flex 상자 안의 글은 `<span>` 하나로 감쌀 것

`.chip`·`.slot`은 `display:flex` + `gap`이다. 글을 감싸지 않으면 **`<sup>`·`<b>`가 저마다 flex 항목이 되어
gap이 글자 사이에 끼어든다.** 실제로 이렇게 깨졌다:

```
<sup>35</sup>S로 <b>단백질</b>을 표지   →  화면:  35 S로 단백질 을 표지
```

브라우저로 열어 보고서야 발견했다(헤드리스 검사는 CSS를 모른다).
→ **검사 [13]에 「칩·칸의 글이 `<span>` 하나로 감싸여 있는가」를 넣어 두었다.** 변이로 물어뜯는 것도 확인했다.
**새 활동을 만들 때 이 절을 복제해 쓸 것.**

### 못 박은 것 (고치기 전에 읽을 것)
- **경계는 1024px.** `@media (min-width:1024px)` 안에만 2단 규칙이 있다.
  **그 아래(태블릿 세로·휴대전화)는 규칙이 하나도 걸리지 않아 지금까지대로 한 줄이다.** 되돌리려면 그 블록만 지우면 된다.
- **`.card.split`의 음수 여백**으로 이 세 장만 화면 쪽으로 넓힌다(최대 1280px). 다른 카드의 980px 글줄은 그대로다.
  ★`transform`으로 넓히지 말 것 — **sticky가 깨진다.**
- **`align-items:start`가 없으면 sticky가 듣지 않는다**(칸이 늘어나 붙을 자리가 없어진다).
- **`.pane-l`은 `max-height:calc(100vh - 20px)` + `overflow-y:auto`.**
  왼쪽 칸이 화면보다 길어질 수 있다(②는 755px). 그때 **그 칸 안에서만** 밀리게 해서, 문서가 밀려 무대가 사라지는 일을 막는다.

### ★함정 — 2단용 DOM 순서를 한 줄로 세우면 순서가 뒤집힌다
DOM은 2단에 맞춰 **「자료(왼쪽) → 조작(오른쪽)」** 순으로 적혀 있다. 좁은 화면에서 그대로 한 줄이 되면
**주입 버튼보다 결과 무대가 위에 놓여**, 누르고 나서 위로 되돌아가야 한다. 실제로 그렇게 됐다.
→ 오른쪽 칸을 `.pr-do`(조작)와 `.pr-q`(문항) 두 덩이로 쪼개고, 좁은 화면에서
`.pane-r{display:contents}` + `order`로 **「조작 → 자료 → 문항」**을 되세운다(= 원래 선형 순서).
세 카드 모두 이 순서가 되는 것을 브라우저에서 쟀다.
**새 활동을 2단으로 만들 때 이 절을 복제해 쓸 것.**

## 4-1. ★함정 — SVG `<text>` 안에 HTML 태그(`<b>`·`<sup>`)를 넣으면 그림이 거기서 끊긴다

**이 파일에 실제로 두 군데 있었다.** 2026-08-25 교차 검토에서 잡았다.

```
'<text …>' + t.name + '</text>'          ← t.name = '<sup>35</sup>S로 <b>단백질</b>을 표지'
'믹서로 세게 흔들어 <b>대장균에 붙어 있던 빈 껍질</b>을 떼어 낸다.'
```

HTML 파서에는 「외래 콘텐츠 이탈」 규칙이 있다 — `svg` 안에서 `b·i·sup·sub·span·p` 같은 시작 태그를 만나면
**`<text>` 와 `<svg>` 를 통째로 닫아 버린다.** `setHTML()` 은 `innerHTML` 이므로 그대로 걸린다.
결과: 그림 안 글자는 그 앞에서 끊기고, 문장 뒷부분이 **무대 밖에 본문 글꼴로 따로 찍혔다.**
④ 1국면에서는 표지 이름과 「대장균」 라벨이 통째로 그림 밖으로 나가 있었다.

★**전에는 900ms 스쳐 지나가 안 보였다.** hc 를 1600ms 로 늦추고 단계별로 세울 수 있게 만들면서 드러났다.

→ `svgText()` 를 두어 `<b>`→`<tspan font-weight="bold">`, `<sup>`→`<tspan baseline-shift="super">` 로 바꾼다.
   **칩·표에 쓰는 HTML 문구를 무대에 옮길 때는 반드시 이것을 거칠 것.**
→ 검사가 **세 무대 × 모든 조건 × 다섯 국면**을 돌며 「무대 SVG 안에 HTML 태그가 없다 · `</svg>` 로 끝난다」를 문다.

## 4-2. ★함정 — 가운데 맞춘 SVG 캡션은 무대 밖으로 잘린다
