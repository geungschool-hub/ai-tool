## 무엇을 하는 활동인가
32염기쌍 무대에서 분기점이 **오른쪽 → 왼쪽**으로 열리고, 학생이 A/T/G/C 단추로 상보 뉴클레오타이드를 직접 붙인다.
**「중합효소는 3′ 말단에만 붙인다」는 규칙을 코드가 강제**하기 때문에, 위 가닥은 연속으로(선도) 아래 가닥은 조각마다 왼쪽→오른쪽으로(지연)
합성할 수밖에 없다 — 학생이 규칙을 외우는 게 아니라 **조작하다가 막혀서 알아낸다**. 조각 4개를 [🔗 연결효소]로 이은 뒤에야 선도/지연이라는 **이름이 공개**된다.
완성 화면에서 딸 DNA 2개를 「원래 가닥 / 새 가닥」 배지로 갈라 보여 주어 반보존적 복제를 눈으로 확인시키고,
💡 더 해보기의 **메셀슨·스탈**에서 보존적·반보존적·분산적 모델의 예상 띠를 그려 실제 결과와 대조한다(분산적은 2회에서만 배제된다는 역사적 논리를 그대로 재현).

## 설계에서 유의한 것 (다음 활동에도 그대로 쓸 것)
- **용어를 미리 주지 않는다.** 선도/지연은 조작이 끝난 뒤 공개. 이름을 먼저 주면 조작 없이 결론에 도달해 버린다.
- **탭 강요 방지**: 각 가닥 6칸씩 직접 붙이면 [⚡ 나머지 자동 합성] 해금(64회 탭 방지). 단 자동은 **연결효소·딸 DNA 확인을 대신하지 않는다**.
- **오답 카운트 = 정리하기 3(수선)의 재료**. 「잘못 붙인 N개를 잘라내고 다시 붙였다 = 세포의 교정·수선」으로 학생 데이터를 문항에 끌어온다.
- ★**CSS와 JS 상수를 손으로 맞춰야 한다** — `.cell`에 `margin:1px`이 있어 실제 열 간격은 `flex-basis(24px)`가 아니라 **26px**.
  `CELL_W=26` · `.arrowrow/.fragrow 832px` · `.fragbox 208px`가 서로 어긋나면 화살표 막대가 엉뚱한 칸을 덮는다(실제로 겪음).

## 검토에서 잡힌 것 (2026-08-13, 전문 = `생물의 유전/활동/_검토결과_20260813.md`)

  빈 칸 위에 표시됐다. → 조각별 막대 4개를 **조각 왼쪽 끝 기준**으로 그리고 연결 후 합치게 수정.
- **[중대] 손상된 저장값에서 `verified`가 무검증 복원** — 상보성이 깨진 가닥인데도 「32/32쌍 ✅」이 뜨던 문제. `daughterCheck` 통과를 조건에 추가.
