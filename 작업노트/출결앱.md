## 2. ★급소 — 라이브와 테스트가 localStorage 를 공유한다

둘 다 `geungschool-hub.github.io` **한 오리진**이다. 저장소가 한 벌이라, 테스트본이 쓴 것이 라이브 앱에 그대로 보인다. 데이터 꼴을 바꾸는 작업에서 이대로 두면 **교사 본인의 실제 출결 기록이 깨진다.**

→ 파일 맨 위 스위치 하나로 **모든 저장소 키**를 가른다.

```js
const TEST_BUILD = true;                 // ← 라이브 승격 시 false
const _KS = TEST_BUILD ? '_test' : '';
```

`_KS` 가 붙는 키 전부 — `attendance_app_v1`(담임) · `subject_att_v1`(교과) · `att_mode` ·
`attendance_zoom` · `attendance_top_offset` · `onboarding_v1` · `notice_subject_240424` · `lbl_homeroom`/`lbl_subject`.
**데이터만 가르면 부족하다** — 설정·안내 플래그까지 갈라야 테스트가 라이브 화면을 안 건드린다.

`TEST_BUILD` 가 켜져 있으면 머리띠가 **갈색**이 되고 제목이 `교과 출결 · 테스트` 가 된다. 눈으로 구분되라고 둔 것이다.

### 서비스워커
- 라이브 캐시 `attendance-2026-vNN` / 테스트 캐시 `attendance-test-vN` — **이름이 달라야 한다.**
- 활성화 때 「이름이 다른 캐시 전부 삭제」면 **테스트본이 라이브 캐시를 날린다.** 접두사로 한정해 둘 것.
- ★**index.html 을 고쳤으면 sw.js 캐시 번호를 반드시 올린다.** 안 올리면 선생님들 폰에 옛 파일이 남는다.

## 3. 교과 출결 기록 모델 (2026-09-16 연강 지원)

`subjData.records[반ID][날짜]` 가 **두 꼴**을 가진다. 연강인 날만 객체가 되고, 단일 교시는 옛 배열꼴 그대로다 — **마이그레이션이 없어서 이미 쌓인 기록은 한 바이트도 안 바뀐다.**

```js
["3-1-4", ...]                 // 단일 교시 — 옛 꼴
{ dbl:1, p1:[...], p2:[...] }  // 연강 (p1=앞교시, p2=뒷교시)
```

**읽기·쓰기는 반드시 접근자만 거친다.** 꼴을 정하는 곳이 `subjSaveDayRec` 한 곳뿐이어야 한다.

| 함수 | 하는 일 |
|---|---|
| `subjDayRec(반,날짜)` | `{dbl,p1,p2}` 로 정규화해 **사본**을 준다 |
| `subjSaveDayRec(반,날짜,r)` | `dbl`이면 객체꼴 · 아니면 배열꼴 · 비면 `delete` |
| `subjDayCount(r)` / `subjDayHas(r)` | 두 교시 합친 건수 / 결과가 있는가 |

- 연강인데 두 교시가 다 비어도 `{dbl:1,p1:[],p2:[]}` 를 **남긴다** — 연강 표시 자체가 기억돼야 한다.
- 연강을 끄면 배열꼴이 되면서 **뒷교시가 함께 버려진다.** 호출부에서 `p2` 를 따로 비울 필요 없다(그렇게 적었다가 죽은 코드가 됐다).
- 화면: 명단 카드 안 ☑연강 → [앞교시][뒷교시] 전환 단추(각 교시 건수가 단추에 붙는다) → 뒷교시일 때만 「⤵ 앞교시 그대로 가져오기」.
- 두 교시를 **가로지르는** 작업은 양쪽을 다 훑어야 한다 — 학생 삭제·현황 집계·복사 텍스트·반 카드 배지.

## 4. 회귀 검사 — 둘 다 돌린다

```bash
node "교사업무/attendance-test/_test_연강.js"        # 74단언 — 연강 기록 모델·화면 문구
node "교사업무/attendance-test/_test_라이브대조.js"   # 112비교 — 라이브본과 똑같이 구는가
```

| 검사 | 묻는 것 |
|---|---|
| `_test_연강.js` | 연강 켜고 끄고 가져오고 삭제할 때 기록 두 꼴이 규칙대로 가는가 |
| `_test_라이브대조.js` | **연강을 안 쓰는 한 새 빌드가 라이브와 한 글자도 다르게 굴지 않는가.** 라이브본과 승격본(`TEST_BUILD=false`)에 **같은 조작 34걸음**을 먹이고 걸음마다 localStorage 전체 + 화면 HTML + 알림 문구를 견준다. 담임 출결(결석·지각·인정·생리통·마감·통계·주간·월간)과 교과 출결(반·결과·현황·복사·삭제·순서·추가·이름·삭제·백업)을 다 훑는다 |

공용 하네스 `_하네스.js` — `index.html` 의 `<script>` 를 통째로 떼어 내 forgiving DOM 위에서 돌린다. 최상위 `let/const` 는 vm 컨텍스트 속성이 안 되므로 같은 스코프에서 손잡이(`globalThis.__T`)를 내보내 집는다. `Date.now` 를 고정해야 두 빌드의 마감 id 가 같아진다. `createElement`+`appendChild` 로 쌓는 화면이라 스텁이 **자식을 기억**해야 한다(처음엔 버려서 빈 것끼리 같다고 통과할 뻔했다 → `nonEmpty` 실질 단언을 둬서 막는다).

★**변이 확인을 반드시 같이 한다**(방법은 [[방법_웹활동_제작표준]]). 2026-09-16 에 연강 검사의 변이 6건 중 2건이 통과해 버렸는데, **검사 구멍이 아니라 겨눈 자리가 틀린 것**이었다 — 위층을 망가뜨려도 `subjSaveDayRec` 이 한 겹 아래서 이미 막고 있었다. 변이는 **실제 방어선**을 겨눠야 한다. 대조 검사는 교과 3·담임 2 변이가 모두 걸렸다. 변이 목록은 검사 파일 맨 아래 주석에.

## 5. 테스트본 → 라이브 승격 절차

1. `교사업무/attendance-test/index.html` → `attendance-checklist_mobile/index.html` 복사
2. **루트본의 `TEST_BUILD` 를 `false` 로** (한 줄)
3. `attendance-checklist_mobile/sw.js` 캐시 번호 +1
4. push → `curl` md5 대조
5. 테스트본은 `TEST_BUILD = true` 인 채로 둔다

★ **되돌리지 않고 고쳐 나간다.** 새 빌드를 한 번 쓴 기기에는 연강 기록이 객체꼴로 남는데, 옛 빌드로 롤백하면 그 기기에서 학생 뷰가 깨진다([[deploy-early-fix-later]]).
